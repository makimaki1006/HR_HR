## 0. 依頼(2026-10-02 ユーザー)

カード内訳(HubSpot の一覧まで掘れるもの)に、取引の「商談種別」の選択肢ごとの合計を足す。
最大の母数から、チーム → 個人へと掘り下げたときに全部追いかけられるように。

HubSpot の定義(main が読み取りで確認):
- 内部名 `negotiation_type`(enumeration)。**内部値とラベルが入れ違っている**。
  - 内部値「代表者商談」→ ラベル「非決裁者商談」
  - 内部値「担当者商談」→ ラベル「決裁者商談」
- シート(KPI営業_商談 / アポ / Cヨミ)の末尾に、列名「商談種別」で**内部値**が入る予定(書き出し側は未反映。今の fixture・本番シートに列は無い)。Rust は列名で読む。

## 1. 今あるもの(コードを読んだ事実)

- 取引 1 行 = `Deal`(mod.rs)。`from_row` は `sheet.get(row, "<列名>")` で読み、列が無ければ空文字。**「列が無い」と「値が空」を区別できない**。区別するには `sheet.col("商談種別").is_some()` を見る必要がある。
- カードの件数は `pool_rows / apo_rows / cyomi_rows`(`DealRow`)を作り、`CARD_KEYS` の述語で数えている(routes.rs)。内訳(`card_deals`)は同じ行。
- 画面の内訳パネル(`drawCardPanel`)は `cardRows(src, base)` で `inScope(owner)` を掛けた行を、チーム → 担当者 → 一覧と降りる。表は `table.cdrill`(E2E の `walk()` がこのクラスで降りる)。
- 下段(⑦⑤⑨・今週来週)の行も `deal_row()` で作る `DealRow`。

## 2. 逆証明: 素朴に作った商談種別の集計が、件数や一覧とずれる入力

「ずれうる入力」を先に列挙し、どのテストで押さえるかを決める。現コードに種別は無いので、これらは**実装の落とし穴の一覧**である(既存の件数にずれは見つかっていない。既存の件数は担当者ごとに 件数 == 行数 がテスト済み)。

| # | ずれ | 入力例 | 素朴な作りで起きること | 押さえ方 |
|---|---|---|---|---|
| N1 | **空の種別を数えない** | 列はあるが値が空の行 | 種別の合計 < カードの件数。空は「(未設定)」の 1 行として数える | Rust: 種別ごとの行数の合計 == by_person の件数。E2E: 表の合計 == 件数 |
| N2 | **内部値とラベルが混在** | 同じシートに「担当者商談」(内部値)と「決裁者商談」(ラベル)が両方 | 別の行として数え、1 つの種別が 2 行に割れる。または片方が「定義外」になる | 変換は「内部値→ラベル」、ラベルはそのまま通す。**行は変換後のラベルで束ねる**。合成入力で両方を混ぜる |
| N3 | **入れ違いの変換を逆に書く** | 内部値「代表者商談」 | 「代表者商談 → 決裁者商談」と素直に書くと、決裁者と非決裁者が丸ごと入れ替わる(件数は合計が合うので気づかれない) | Rust ユニットで 4 通りを具体値。変換表の 2 行を入れ替えると落ちることを逆証明 |
| N4 | **定義外の値** | 「新種別」「constructor」など | 表に無い値を捨てると合計が減る。JS のオブジェクトをキーにすると `constructor` / `__proto__` が壊れる | 値そのまま + 「(定義外)」で数える。JS は `Map` で束ねる。合成入力に定義外を入れる |
| N5 | **前後の空白・全角空白** | 「 担当者商談」 | 変換表に当たらず「定義外」になり、同じ種別が割れる | 前後の空白は落としてから引く(空白だけは「(未設定)」) |
| N6 | **列が無いシート** | 今の fixture・本番 | 全行が「(未設定)」になり、「未設定が全件」と読める(列が無いだけなのに) | 行に値を付けず、payload に `negotiation_type_available:false`。画面は「商談種別: 未取得」を出し、表を出さない |
| N7 | **シートごとに列の有無が違う** | 商談シートには列があり、アポ・Cヨミには無い(書き出しの反映が揃わない期間) | ① と ⑨ に「(未設定)」が全件出る | 有無はシート(= カードの出どころ `pool/apo/cyomi`)ごとに持つ(`negotiation_type_sheets`) |
| N8 | **種別で絞った一覧と件数がずれる** | 種別を押した後にチーム → 担当者へ降りる | 種別の絞りを下の段で外す/二重に掛けると、一覧の行数が種別の件数と合わない | 絞りは行の配列の `filter` 1 回(種別・チーム・担当者・BPO・区分を同じ行集合に順に掛ける)。E2E で全段・全種別の一覧行数 == 件数 |
| N9 | **種別ごとの件数を別経路で数える** | `by_person` に種別キーを足して数える | 述語を二重に持つとカード側とずれる(④ は日付ではなく区分、① の BPO 窓は別、など) | サーバは**行に種別を持たせるだけ**。件数は同じ行から数える(`by_person` 等の既存キーには足さない) |
| N10 | **担当なし(owner "")・名簿外・チェックで外した人** | 既存の `inScope` | 種別の表だけ別の絞り込みで数える | 種別の表の行も `cardRows()`(= `inScope`)の出力から作る。担当なし(`personPick === ''`)でも降りられる |
| N11 | **集計除外・月またぎ・同じ取引が複数カード・BPO の窓** | 既存の `keep_counted` / 月フィルタ / `CardSrc` ごとの行 | 種別のために別の材料を読み直すと除外者・月外の行が混ざる | 種別は `Deal` の項目として入口で読み、`keep_counted` 後の行にそのまま乗る。`bpo` はカードごとの規則のまま |
| N12 | **⑥⑤ の分子と分母** | 分子 = 実施 / 回収済み、分母 = ④ | 分母だけ種別で数え、分子を数え忘れる。または分子が分母より大きくなる | 表に分子・分母の 2 列を出し、どちらも `cardRows` の同じ行から数える。E2E で分子 ≤ 分母、合計 == 見出し |
| N13 | **種別の値が `;` で複数入る** | 「担当者商談;代表者商談」(enumeration は単一値のはずだが、書き出し側の不具合で起きうる) | `;` で割って数えると 1 取引が 2 回数えられ合計が件数を超える | **割らない**。全体を 1 つの値として扱う(表に無いので「(定義外)」)。1 行は必ず 1 種別 |
| N14 | **画面に内部値が出る** | 行のラベル化漏れ | 「代表者商談」「担当者商談」が画面に出て、意味が逆に読まれる | サーバでラベル化して返す(JS は変換しない)。E2E で画面全体に内部値の文字列が無いこと(定義外の値を除く) |
| N15 | **並び順が毎回違う** | `HashMap` の順 | 種別の行が入れ替わり、全社 → チーム → 個人で上下がぶれる | 並びは「決裁者商談 → 非決裁者商談 → (未設定) → 定義外(名前順)」で固定。順の定義は Rust の 1 か所、payload の `negotiation_type_order` で JS に渡す |

見つけたずれ: 現コードの既存の件数にずれは無い。上は新しい集計を足すときに起きる箇所で、テストで先に押さえる。
実コードの既存の問題として 1 点だけ確認した: **`Deal` は「列が無い」と「値が空」を区別しない**(N6/N7 の元)。種別では `Option` で区別する。

## 3. 設計

### 3.1 サーバ

- `Deal.negotiation_type: Option<String>`: シートに「商談種別」列があれば `Some(生の値)`、無ければ `None`。
- 変換は mod.rs の 1 か所に置く。
  - `NEGOTIATION_TYPE_MAP: [(内部値, ラベル); 2]` = `("代表者商談","非決裁者商談")`, `("担当者商談","決裁者商談")`
  - `negotiation_type_label(raw) -> String`: 前後の空白を落とす → 空なら `(未設定)` → 内部値ならラベル → すでにラベルならそのまま → それ以外は `値(定義外)`
  - `negotiation_type_rank(label)`: 決裁者商談 0 / 非決裁者商談 1 / (未設定) 2 / 定義外 3
- `DealRow.negotiation_type: Option<String>`(`skip_serializing_if = Option::is_none`)。`deal_row()` が `Deal` から作る。**列が無いときは行にキーを出さない**(既存の行の JSON は 1 バイトも変わらない)。
- payload に追加(既存キーは変えない):
  - `negotiation_type_available: bool`(3 シートのどれかに列がある)
  - `negotiation_type_sheets: {pool, apo, cyomi}`(カードの出どころごとの有無)
  - `negotiation_type_order: ["決裁者商談","非決裁者商談","(未設定)"]`(固定部分の並び)
- 件数は行から数える(N9)。`by_person` / `by_team` には種別のキーを足さない。

### 3.2 画面

- 内訳パネルに「商談種別」の表(`table.ntt`)を足す。`cdrill` とは別クラス(E2E の `walk()` が降りる表と区別する)。
  - 段ごとに、その段の行(全社 = 絞り込み後の全行 / チーム = そのチームの行 / 担当者 = その人の行)を種別で束ねる。列: 件数・内 BPO。⑥⑤ は分子・分母。合計行はその段の件数。
  - 種別のボタンを押すと、その種別だけに絞る(`cardNt`)。絞りは下の段(チーム → 担当者 → 一覧)にも効き、バッジ(「商談種別: 決裁者商談 ✕」)で外せる。
  - 区分チップ(④⑥⑤)・内 BPO と併用できる。種別の表の件数は「区分の絞りを掛けない行」から数える(⑥⑤ で分子・分母を並べるため)。
- 列が無いシート(カードの出どころごと)では「商談種別: 未取得」を出し、種別の表・絞りは出さない。
- 取引一覧の行に商談種別(ラベル)を添える。

## 6. レビュー指摘の修正(2026-10-03 追記)

Opus レビューの 3 点を、先に落ちるテストを書いてから直した(コミット: e1a4f52 テスト → 9693e2b E2E 補正 → e264466 修正)。

### 6.1 `;` 区切りの値の表示

- 方針は据え置き: `;` 区切りは割らず 1 件として数える(合計がカードの件数を超えないため)。
- 追加した決め: `;` で割る → 各部分の前後の空白(全角含む)を落とす → 空の部分は捨てる → 同じ部分の重複は 1 つにする。
  残りが 0 なら `(未設定)`、1 つなら単独の値と同じ(内部値はラベルへ、表に無ければ `(定義外)`)、
  2 つ以上は各部分を同じ変換表でラベルに直して `;` でつなぎ、**全体に `(定義外)` を 1 回だけ**付ける(並びは入力のまま)。
  例: `担当者商談;代表者商談` → `決裁者商談;非決裁者商談(定義外)` / `担当者商談;新種別` → `決裁者商談;新種別(定義外)` /
  `担当者商談;` → `決裁者商談` / `;` → `(未設定)` / `担当者商談;決裁者商談` → `決裁者商談`。
- 修正前 FAILED(`cargo test --lib sales_kpi::tests::negotiation_type`、コミット e1a4f52 の時点):
  `test result: FAILED. 12 passed; 7 failed; 0 ignored; 0 measured; 3855 filtered out`
  (left: `"担当者商談;代表者商談(定義外)"` right: `"決裁者商談;非決裁者商談(定義外)"` ほか。複数値 3 件、並び 2 件、テンプレ直書き 1 件、fixture 突き合わせ 1 件)。
- E2E(`--negtype` の dump に `担当者商談;代表者商談` と `担当者商談;` を追加。修正前のテンプレ・Rust): 画面に内部値「代表者商談」「担当者商談」が出る NG が 407 件。

### 6.2 区分 × 種別

- 原因: 種別の表は区分(実施・未実施・未処理・要判定、回収済み・未回収)を掛けない行から数えていたので、区分を選んでも合計が全体のままだった。
- 修正: 種別の表は「内 BPO → 区分」まで掛けた行から数える(種別だけ掛けない)。種別を押した先の一覧は従来どおり区分と種別の両方を掛ける。
  ⑥⑤ で区分を選んでいるときは件数列の見出しを `件数（区分名）` にする(分子は区分が分子と同じときだけ 0 でなくなる)。
- E2E に追加: `nt_seg_check`。④⑥⑤ の各区分を選んだまま、全社 → チーム → 担当者 → 一覧の各段で 種別の合計 == 区分の件数、
  種別を押した先の一覧の行数 == その種別の件数、内 BPO を併用したとき 種別の合計 == 区分の内 BPO。

### 6.3 並びの決め方を 1 か所に

- 選んだ方: **Rust で決めて JS は従う**。`negotiation_type_rank` を本番コードで使う形にした(消す案は採らない)。
- 理由: 定義外のラベルは月ごとに変わる(`新種別(定義外)`、複数値)。JS で並べると、固定順の直書き('(未設定)')と名前順の比較(`localeCompare`)を持たざるを得ない。
  Rust が `negotiation_type_order_of` で「固定 3 つ + 実際に出てきた定義外(コードポイントの名前順)」を payload の `negotiation_type_order` に入れ、
  0 件でも並べる 2 種別は `negotiation_type_fixed` で渡す。JS は `order.indexOf` で並べ、`fixed` を足すだけ。
- 並びは `決裁者商談 → 非決裁者商談 → (未設定) → 定義外` のまま。定義外が無いとき `negotiation_type_order` は従来と同じ 3 つ。
- テスト: payload の order を具体値で(fixture に定義外あり: `[決裁者商談, 非決裁者商談, (未設定), 新種別(定義外), 決裁者商談;非決裁者商談(定義外)]`、
  なし: 固定 3 つ)、テンプレートに `(未設定)` の直書きと order 周辺の `localeCompare` が無いこと(`include_str!` で検査)。
