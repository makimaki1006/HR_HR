## ループ1: 何が言えるか（実データで確認済み）

### 🔴 発見1: 求人票の「職種名」を変えるだけで効く、と数字で言える

`insight_kw_term_monthly` に 14 か月ぶんの検索語シェアがある。
「事務」という職種で、求職者が使う言葉が**14 か月連続で入れ替わっている**。

```

「事務」      45.3%    →    26.8%     -18.5pt
「一般事務」    5.3%    →    19.9%     +14.6pt
```

月次で追うと、途中で反転せず一貫して動いている（単調度 77%）。1 か月の揺れではない。

**言えること:** 求人票の職種名を「事務」のままにしている企業は、
求職者が実際に打つ言葉からずれていっている。

同じ型が他にもある（直近クリック 1,000 以上、単調度順）:

### 🔴 発見2:「アルバイト」が複数職種で一斉に伸びている

職種の話ではなく**雇用形態の書き方**の話。


見つけてもらえる量が変わる可能性がある。職種名ではなく雇用形態の語を足す話なので、
求人票の修正コストが低い。

## 使ってはいけない / 注意が要るもの

### 🔴 `insight_pref_unique` の lift は「効き目」ではない

「その県だけで効く検索語」として lift（全国比）が入っているが、**絶対値に意味がない**。

```
鳥取県「米子鬼太郎空港」  全国比 383.33倍
島根県「出雲公共職業安定所」全国比 383.04倍
```

383 が並ぶのは「その県にしか出ない語」が 1/47 で割られただけ。
県ごとの語数に偏りがあり（茨城 31語 ⇔ 東京 295語）、**語数が少ない県ほど lift が跳ねる**。

→ lift は「珍しさ」として扱い、**「効き目」と読ませない**。クリック数を併記する。

### 🔴 検索語に社名・施設名が 6.6% 混ざっている

```
3,086語中 205語 (6.6%) が「株式会社」「公共職業安定所」「空港」「工場」を含む
例: 「ヤンマーキャステクノ株式会社」「隠岐汽船株式会社」「米子鬼太郎空港」
```

そのまま顧客に見せると**他社名が画面に出る**。伏せる規律が要る。
（既存ルール: 外部公開素材に SalesNow と書かない、検索エンジンを名指ししない、と同じ系統）

### 属性データは 2 つしか使えない

`insight_kw_attr_trend` の 8 属性のうち、実用に足るのは 2 つだけ。

| 属性 | 非ゼロ率 | 最大 | 平均 |
|---|---|---|---|
| 条件（働き方） | **100%** | 88.6% | 34.9% |
| シニア | **93%** | 37.7% | 5.1% |
| 主婦・主夫 | 39% | 8.6% | 0.6% |
| 語学 | 24% | 7.7% | 0.3% |
| 外国人 | 19% | 5.5% | 0.3% |
| 未経験 | 31% | 6.6% | 0.4% |
| 学生 | 8% | 3.3% | 0.1% |
| 資格 | **4%** | 55.8% | 0.5% |

語数で層別しても平均が単調に動かないので、**ゼロは「母数不足」ではなく本当に少ない**と読める。

→ ペルソナを 8 属性で作るのは無理。**「条件」と「シニア」の 2 軸**が現実的。

## ループ3: Indeed の語を求人票に繋ぐ

### 何を作ったか

`src/indeed/wordbrief.rs`（新規）。職種ごとに、求職者が打っている語を
**データだけで**確定させる。LLM は使わない。

```
出すもの          いま打たれている語 / 14 か月で伸びた語 / 落ちた語
落とすもの        社名・施設名を含む語（実測 3,086 語中 205 語 = 6.6%）
動きの判定        3pt 未満は拾わない / 向きの一貫が 60% 未満は拾わない
月の揃え方        14 か月ずっと上位 10 位に出ていた語だけを判定に使う
```

既存の「探すときに使われた言葉」は**最新月の多い順**なので、向きが分からない。
「事務」は最新月でも 26.8% で 1 位なので、あの表では何も起きていないように見える。

### 語は 3 つに仕分ける（これが要だった）

最初、上位語をそのまま「職種名はこの語に寄せる」と渡していた。実際に画面に出したら:

```
ホールスタッフ:「カフェ」「飲食店」「ネイルok」「カフェスタッフ」「高校生ok アルバイト」
                → 「職種名はこの語に寄せる」
```

「ネイルok」を職種名にすることはない。**書く場所が違う語が混ざっていた。**

```
職種名    事務 / 一般事務 / データ入力 / カフェ / アパレル
雇用形態  事務パート / パート事務 / 短期 アルバイト
条件      土日祝休み / ネイルok / 主婦パート / 高校生ok アルバイト / 50代
```

優先順位は 条件 > 雇用形態 > 職種名。「主婦パート」は両方含むが、
「主婦歓迎のパート」を探している語なので条件側。テストで固定した。

### 求人票生成から引く口

```
GET /api/indeed/wordbrief?title=事務
```

返りの `guide` が、LLM にそのまま渡してよい 1 文。**数字を含まない。**
工程⑦の `validate_generated` が「原文に無い数字」を弾くので、
ここで「45.3% → 26.8%」と書くと原稿ごと差し戻されるか、
弾かれずに出て根拠のない数字になる。どちらも困る。

実際の返り:

> この職種を探している人が実際に打っている職種名は「事務」「一般事務」「データ入力」。
> 求人票の職種名はこの語に寄せる。職種名と雇用形態を並べた「事務パート」「パート事務」
> でも探されている。条件として打たれているのは「土日祝休み」。当てはまるものは条件欄に
> 書く（職種名には入れない）。打たれる回数が増えている職種名は「一般事務」。
> 減っている職種名は「事務」なので、これだけに頼らない。

### 🔴 節を指した URL が効いていなかった（見つけて直した）

別調査（scan-ui）が `location.hash` の扱いを読み出してくれたので、確かめた。

```
まっさらな文脈で `/?tab=...#sec-4` を開く
  scrollY=0 / hash="#sec-4" / 印は DOM にある（画面内 1745px）
  → URL には節が付いているのに画面は先頭のまま
```

理由（scan-ui の読みどおり）:

```
1 ブラウザは文書読込時に #sec-4 へ送ろうとする
2 その時点の #content は「読み込み中...」で、sec-4 の印はまだ無い
3 中身は htmx.ajax で後から届く
4 誰も送り直さない（afterSettle のリスナーにハッシュを見るものが無い）
```

つまり**節を指した URL を人に送っても、相手の画面は先頭のまま**だった。
左の列で節に飛べるようにした以上、これは作りかけになる。

`templates/dashboard_inline.html` に最小の手当てを入れた。

```
ハッシュは読み込み直後に捕まえる（hx-push-url があとで消すため）
最初の afterSettle で印が DOM に来ていたら、その節へ送る。1 回で使い切る
ハッシュが無ければ何もしない
スクロール維持の塊より後に登録する（向こうも requestAnimationFrame を使うため）
```

実測（まっさらな文脈で 3 本）:

```
overview/sec-2   scrollY=961（最大1390）  印 50px「なぜそうなったか（数字の内訳）」
industry/sec-3   scrollY=3191（最大3246） 印 50px「分類別の定点表」
overview/sec-4   scrollY=1390（＝最大）   最後の節なので文書の末尾で止まる
ハッシュ無し      scrollY=0 / 図 4（未初期化 0）/ コンソールエラー なし
```

### hash は 6 経路のうち 5 つで落ちる（残りは未対応）

scan-ui が調べた結果。上で直したのは「再読み込み時の空振り」1 つだけ。

| 経路 | hash は残るか |
|---|---|
| `?tab=` の除去（`dashboard_inline.html:474`） | 残る |
| htmx の `hx-push-url`（タブ・面の切替） | **消える** |
| `DIRECT_ACCESS_GUARD` の `?tab=` 組み立て（`indeed/tab.rs:45-52` ほか 6 箇所） | **消える** |
| `sessionStorage` への記憶（`entryKey()` は `pathname + search`） | **保存されない** |
| 再読み込み時のアンカースクロール | **直した**（上） |
| 戻る/進む（`onHistoryNavigation()` が hash を見ない） | **反応しない** |

scan-ui の提案は「節の位置は hash ではなく**クエリ（`&sec=`）に乗せる**」。
クエリなら `htmx:configRequest` が拾って `rememberTab()` に入り、
`rememberedFor()` で復元され、`hx-push-url` でもガードでも持ち回される。
**hash のままだと 6 経路のうち 5 つに手当てが要る。** 今回は 1 つだけ直した状態。
