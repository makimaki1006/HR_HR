## 2. 1 画面ずつの進め方とユーザー回答

### 2.1 各画面の手順(全画面共通)

1. 旧画面との差分を洗い出す(機能・入力・数値の出どころ・状態・エラー)。
2. 逆証明(段階 A): 壊れる入力・状態を先に列挙する。
3. 落ちるテストを先に書き、赤を確認してから実装する。
4. 3 段階テスト(静的: `tsc`/ESLint/fmt/clippy、ユニット: Vitest/cargo test、統合: 契約テスト・PR E2E)。件数は実ログで示す。
5. 旧新一致の確認(値で比較。要素の存在では判定しない)と Opus によるレビュー。
6. マージ。**ナビは旧画面のまま**(React 版は `/app/{screen}` で到達できるだけ)。
7. ユーザーが試す。
8. ナビを React 版に切り替える(`src/handlers/nav.rs` の `NavKind::App`)。
9. 1 リリース後に旧 URL を 302、その次に旧テンプレート・旧 E2E を削除。

React 画面の部品: `frontend/src/screens/<screen>/`、`frontend/src/entries/<screen>.tsx`、`frontend/vite.config.ts` の input、`src/handlers/spa_shell.rs` の `KNOWN_SCREENS`。型は Rust 構造体から ts-rs で `frontend/src/generated/` に生成(`app_api.rs` の export に追記)。
