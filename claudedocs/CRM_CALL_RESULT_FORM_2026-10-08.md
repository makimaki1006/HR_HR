# 架電結果の入力欄 (下書きのみ) 2026-10-08

架電画面 (`/app/crm`、CallQueueScreen) の中央の列の下端に、架電結果の入力欄を追加した。
**HubSpot には何も書き込まない。** 入力はこの画面のタブ (sessionStorage) に下書きとして残るだけ。同じブラウザでも別のタブには出ず、タブを閉じると消える。

- 画面: `frontend/src/screens/crm/CallResultForm.tsx` / `result-form.css`
- 規則と変換: `frontend/src/screens/crm/callResultModel.ts`
- 選択肢の読み込み: `frontend/src/screens/crm/useResultDefinitions.ts`

## 1. 項目

選択肢は HubSpot の定義から読む。実データでは `GET /api/crm/metadata`、架空サンプルでは `mocProperties.ts` (2026-10-01 のスナップショット)。
実データで取得に失敗したとき、または必要な項目が応答に無い・型が想定と違う (日付・文字の項目) ときはエラーを出し、入力欄を出さない (架空の選択肢で代用しない)。画面のエラーには日本語の項目名だけを出し、内部名はブラウザのコンソールに出す。

`/api/crm/metadata` の deals 許可リスト (`src/handlers/crm_metadata.rs`) には、下表の 13 項目がすべて入っている (bpo_57 は 2026-10-08 に追加)。食い違いは `cargo test` (`deal_allowlist_covers_every_call_result_form_property`) と vitest (`metadataContract.test.ts`) で検出する。

共通の規則:

- 選択肢は内部値で持つ (例: 表示「現在使われておりません」→ 値「使われておりません」)。hidden の選択肢は新しく選べない。
- 結果を変えて見えなくなった項目は、値が残っていても検証・送信の対象にしない。
- 「今日」の区切りは JST の 0 時。
- 下書きは案件ごと (鍵は `モード:案件ID`)。案件の切り替え・絞り込み・続きの読み込み・折りたたみでは消えない。下書きを消すのは「下書きを消す」だけ (記録済みの印も消える)。
- 「記録して次へ」(Ctrl+Enter / ⌘+Enter) は、記録済み(未送信) の印を付け、一覧で次の未記録の行を選ぶ。下書きは残す。HubSpot には送らない。
- 記録済みの案件の入力を書き換えると、記録済みの印だけを外す (記録したときの内容と変わったため)。入力欄の下端に「内容を変えたので「記録済み」の印を外しました。もう一度「記録して次へ」を押してください。」と出す。
- sessionStorage に書けない (ブラウザの設定・容量) ときは、入力欄に赤い注意 (role=alert)「入力を残せていません」を出し、状態と一覧の印を「…(この画面を閉じると消えます)」にする。「記録済み(未送信)」とは出さない (headless-crm-design §12)。
- 不通時チェック・ブロック理由は、一覧と詳細でも入力欄と同じ HubSpot の表示ラベルで出す (定義を読めていなければ値のまま)。
- 画面から発信した通話が終わると、その案件の入力欄の見出しに通話時間を出し、結果のボタンにフォーカスを移す (1 通話につき 1 回)。Zoom の枠の案内も、選んでいる案件と結び付いた通話のときだけ「架電結果に入力できます」と出し、それ以外 (Zoom の枠から直接かけた・別の案件の通話) は「架電先を選んでから入力してください」と出す。

入れていない項目 (提案止まり。使うかはユーザー確認): bpo_41 担当者会話レベル、bpo_46 断り理由、bpo_20 最終架電日 (自動で今日を入れる案)。

## 3. 将来の書き込み用の変換 (まだ使っていない)

`toHubSpotPatch(draft, defs, today)` は有効な下書きを Deal の PATCH 本文 `{ properties: { 内部名: 文字列 } }` にする。無効なら null。

- 表示中の項目で空でないものだけ。許可リストは `RESULT_PROPERTY_ALLOWLIST` (FIELD_PROPERTY とは別に書いた 13 項目。dealstage・bpo_20 は入らない)
- 日付・文字の項目は、定義の型 (date / string) が想定と違えば無効にする
- 日付は JST の暦日 `YYYY-MM-DD` のまま (Date に通さない。通すと 1 日ずれる)
- 時間・選択肢は選択肢の値 (`'9:15'` など)
- 今回の結果そのものは送らない (HubSpot のプロパティではない)

この PR では呼び出していない。

6. 「最終架電日」は今、誰がどうやって入れていますか (手入力・ワークフロー・自動)？ 架電のたびに今日の日付を入れてよいですか？
7. 「担当者会話レベル」と「断り理由」は架電のたびに入れてもらう項目ですか？
8. 番号違いのとき、不通時チェックは必須にしてよいですか？

## 5. やっていないこと

- HubSpot への書き込み (PATCH・Note 作成・Call への紐づけ)。書き込み用のバックエンドの口も作っていない
- Durable Retry / Pending Sync (headless-crm-design §10、ADR-009)
- 冪等性 (operation_id / zoom_call_log_id、ADR-010)
- 既存値の読み込み (タスクメモ等を初期表示して編集する)。いまは毎回空から入れる
- 保存状態の緑 / 黄 / 赤 (§12)。いまは「下書き(HubSpot 未送信)」と「記録済み(未送信)」だけで、保存したとは表示しない
- 下書きはこのタブの sessionStorage だけ。タブを閉じると消え、同じブラウザの別のタブ・他の端末・他の人には見えない
