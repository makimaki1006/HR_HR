# 架電 CRM: 全員が全件を見られる・所有者を選べる (2026-10-07)

`CRM_ROLES_FROM_HUBSPOT_2026-10-07.md` の「管理者以外は自分の担当分だけ」を、この文書の規則に置き換える。
決定 (ユーザー 2026-10-07): 「管理者以外も含めて、全員が所有者 (HubSpot owner) をプルダウンで選んで他人の取引を見られる。開いたときの初期値は自分。HubSpot で全件見えている状態と同じ」。

## 1. 規則

1. **使えるか** (変更なし): Google OIDC で本人確認済み・会社ドメイン・無効化されていない人。パスワードログイン・社外ドメイン・未ログインは、これまで通り HubSpot を呼ばずに拒否 (401 / 403)。
2. **見られる範囲**: CRM を使える人は全員、全件を読める (キュー・個別 Deal / Contact / Company・ワークスペース・担当者一覧)。
   「自分が担当でキュー条件に合うものだけ」という関門 (`record_gate.rs`、ワークスペースの関門) は CRM の利用者には掛けない。
3. **管理者かどうか**は次の 2 点にだけ効く: ① キューの既定 (管理者 = 全員分、それ以外 = 自分) ② 管理者だけの機能 (管理画面、役割変更、hubspot-check)。管理者 = `ADMIN_EMAILS` または `accounts.role = admin` (変更なし)。
4. **キューの `owner`**: 未指定なら既定。`all` / `unassigned` / `me` / 任意の owner id は全員が指定できる (他人を指定すると 403 `forbidden_owner` になる経路は無くした)。
5. **自分の owner が見つからない人**: `owner` 未指定または `me` のとき、403 ではなく **409 `owner_not_resolved`**。全員分には倒さず、検索もしない。画面は「所有者を選んでください」と一覧を開いて選択を促す。`all` や他人の指定なら見られる。
   Owners の取得そのものが失敗したときは従来どおり HubSpot のエラー (502 / 503 など)。
6. `accounts.role` は admin 判定にだけ使う (変更なし)。DB のスキーマ変更・書き込みの追加なし。

## 2. 許可表

| 操作 | 管理者 | 管理者以外 (owner あり) | 管理者以外 (owner なし) |
|---|---|---|---|
| metadata | 可 | 可 | 可 |
| キュー (既定) | 全員分 | 自分 | 409 `owner_not_resolved` |
| キュー `owner=all` / `unassigned` / 他人の id | 可 | 可 | 可 |
| キュー `owner=me` | 可 (owner があれば) | 可 | 409 `owner_not_resolved` |
| 担当者一覧 `/api/crm/owners` | 可 | 可 | 可 |
| 個別 Deal / Contact / Company / ワークスペース | 全部 | 全部 | 全部 |
| 不在の id・アーカイブ済み | 404 | 404 | 404 |

パスワードログイン・社外・未ログイン・無効アカウントは、どの行も HubSpot を呼ばずに 401 / 403 (テストで HubSpot 呼び出し 0 回を確認)。

## 3. 実装の場所

- `src/crm/rbac.rs`: `CrmRole::is_admin()` を追加。`reads_all_records()` は役割が決まっていない最小権限 (`User`、通常の経路では来ない) 以外は true。
- `src/crm/call_queue.rs`: `forbidden_owner` を廃止。`effective_owner` の既定を `is_admin()` で決める。`me` を解決できないときは 409 `owner_not_resolved`。`scope.teams` は自分 (me) を見ているときだけ引く (参考情報)。
- `src/crm/owners.rs`: 役割の確認を外した (認可 → HubSpot 設定 → 一覧)。
- `src/crm/routes.rs` / `workspace.rs` / `record_gate.rs`: ロジックは変更なし (`reads_all_records()` が true なら関門を通らない)。関門は最小権限 `User` に対する安全側の備えとして残してある (テストあり)。
- 画面: `OwnerFilter.tsx` を全員に出す (凡例「所有者」。全員分は明示の `all` を送る = 空にすると「自分」に戻るため)。`CallQueueScreen.tsx` が初期値を応答の `scope.owner` から決め、注記を「所有者: ○○ を表示中」にした。409 のときは再試行ではなく選択を促す表示。

## 4. 画面の動き

- 開いた直後: `owner` は未指定でサーバの既定。管理者は「全員分」、それ以外は「自分」が選ばれた状態で表示される。
- 一覧から他人を選ぶ: 在籍者のみ (退職者は「退職者も表示」で切り替え)。同名は email で見分ける。
- 自分の owner が見つからない人: 「所有者を選んでください」と一覧が最初から開く。選ぶとその所有者で読み直す。

## 5. ユーザーが行うこと

- スキーマ変更・SQL 実行・環境変数の追加は不要。
- メール (email) は担当者一覧に含まれる。利用者が社内の人だけなので、同名の見分けのために残している。

## 6. 残課題

- ナビの「CRM」リンクは `nav::crm_visible(is_admin)` により管理者にしか出ない (今回は未変更)。管理者以外が使うには `/app/crm` を直接開くか、ナビの出し方を別途決める必要がある。
- 全員が全件を読めるので、HubSpot の個人情報 (電話番号・メール) は会社アカウントを持つ全員に見える。HubSpot 側と同じ前提。
