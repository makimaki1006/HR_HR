# 架電担当向け入力要件（デモ用の暫定案）

実定義照合後のMOC（2026-10-01）: 以下の初期候補より、[取得した定義](account-property-findings.md)を優先する。会話相手はDeal `bpo_40`、関心度は `bpo_42`、次アクションは `bpo_45`、タスクメモは `bpo_16`。次回日は `bpo_13`、時間は `bpo_14` の別入力とし、実選択肢45件の値を保持する。募集職種・人数・課題感・募集種別は会社へ寄せず、案件（Deal）単位で入力する。

MOCの暫定チェック: 再架電の約束または次アクションが再架電なら日付と時間が必須。アポ獲得なら商談日・時間・方法、架電停止なら理由が必須。停止希望の選択または停止理由の入力で発信デモを無効化する。これは実運用の必須条件や全ブロック条件を確定するものではない。操作結果の6選択肢はMOC専用で、Call結果への実マッピングは未確定。記録は画面内のみで、再読み込みで消える。

2026-10-01。実運用の必須項目とHubSpotプロパティへのマッピングは未確定。まず架空データのUIで入力負担を確認する。既存の架電結果、メモ、次回日時に、会話相手・関心度・次のアクションを追加する。任意項目は展開式にし、不在時の入力負担を増やさない。

| 項目 | 必須条件・入力 | 保存先の候補（未実装） |
|---|---|---|
| 架電結果 | 毎回必須。会話、不在、再架電約束、アポ、番号違い、架電停止 | HubSpot Call Activityの結果。既存選択肢・内部値を照合 |

「資料送付を依頼」は依頼内容の記録であり、メールを送信しない。「営業担当へ引き継ぎ」はアクションの記録であり、通知や担当者変更を行わない。関心度と次のアクションは今回のUIでは独立した任意項目で、架電結果の検証を置き換えない。

一覧は12件の架空コンタクトを使い、独立したスクロール領域と固定列見出しを用意する。検索（会社・担当者）、担当オーナー、対応状態、電話番号の有無をANDで適用する。絞り込みで非表示になっても下書きを保持する。次の対象は現在の絞り込み内から選び、記録済み・後回し・番号なしを除く。通話中は絞り込み操作を止め、通話中の行が隠れないようにする。

追加の架空コンタクトは一覧デモ専用。実データ読み取りで12件固定や全件取得を前提にせず、サーバの権限範囲とページングに従う。将来の「さらに読み込む」は検索条件・並び順・取得済みカーソルを保つ設計が必要。

実運用前の確認事項: 架電結果の既存内部値、次回日時の保存先とタイムゾーン、架電停止条件、アポ時に必要な日時・引き継ぎ先、必須メモ条件、関心度の定義、Workflow発火条件。今回のUIにアポ日時・顧客情報変更・自動通知は追加しない。

実保存はRustの認可・検証境界を通し、HubSpotを正本とする。CREATEの冪等性とDurable Retry / Pending Syncが成立してから接続する。新DBは追加しない。デモ入力は画面メモリだけに保持し、再読み込みで消える。

## 顧客名から開く詳細プロパティ

実装前の計画: 顧客名ボタンで一覧の直下に詳細行を展開・折り畳みする。既存Contact / Companyのプロパティを表示し、ヒアリングで更新する項目に入力欄を付ける。下書きのキーをContact ID / Company IDと項目名に分け、同じ会社を複数担当者が指す場合に矛盾した下書きを作らない。

| 領域 | 入力可能項目 | 扱い |
|---|---|---|
| 担当者情報 | 役職・メール・電話番号 | Contact単位の下書き。300文字以内。未確認は空欄 |
| 会社情報 | 業種・市区町村・従業員数・会社電話番号 | Company単位の下書き。同じ会社の別担当者の詳細にも反映。300文字以内 |
| 採用ヒアリング | 職種・予定人数・開始時期・課題や条件 | Company単位の暫定ヒアリング項目。各1000文字以内。「未定」などを受け付ける自由入力 |
| その他の既存プロパティ | 担当オーナー・ステータスなど | 参照のみ。架電担当が変更できる範囲は実接続時にRustの権限で定義 |

折り畳み・絞り込みでも下書きを保持し、別顧客のContact項目は混ざらない。架電結果をデモ記録した後も詳細の下書きを編集できる。詳細入力はHubSpot保存済みを意味せず、架電結果のデモ記録とは別の下書きとして表示する。入力電話番号で実発信や架電可否の変更は行わない。

実接続前にContact / Company更新の確定操作、空欄で既存値を消すルール、メール・電話・人数のサーバ検証、会社情報の競合編集、採用ヒアリングの既存プロパティとの対応を決める。採用項目は未確認のHubSpot内部名を新設せず、既存の保存先とWorkflowを確認してから接続する。
