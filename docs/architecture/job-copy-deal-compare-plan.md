# 求人文面管理の取引絞り込み・横断比較

依頼日・設計日: 2026-10-11。対象は `/app/job-copy` の「HubSpot の求人」。PC幅1440・1920で確認する。

## 調査と実装方針

- Rust / Axum、既存React画面、HubSpotを正本とする構成を維持する。CRM配下、保存基盤、HubSpotの項目や関連への書き込みは変更しない。
- 既存一覧は6時間ごとに更新するメモリ上の索引。50件のページ分けと都道府県・職種・媒体の絞り込みがある。取引の関連はなく、固定一覧の横断比較はHubSpotの全求人には使えなかった。
- 索引に取引の関連と名称、本文の列から得られる比較用の条件、本文履歴の変更日時、応募関連の件数を追加する。本文・履歴・応募者の属性は索引に保持しない。従来のページごとの応募関連読み取りを、索引更新時の一括取得に移す。画面には索引時点の値であることを明示する。
- 部分取得・関連の欠落・関連のページ取得失敗では索引を置き換えない。失敗を「取引なし」や応募0件にしない。古い完成済み索引を維持する。
- 取引名の検索・取引選択・ページ移動・表の並べ替えではHubSpotを呼ばない。候補は索引から最大30件。1求人の複数関連を保持し、取引なしも選択できる。
- 表の条件と並べ替えはページ分け前に適用する。給与は金額を数値順、本文の最終変更日は本文プロパティの履歴から取得する。他の項目変更日時・取得日時を本文変更日に代用しない。同じ値の再保存はさかのぼる。全20履歴が同値で開始時点を確認できなければ未取得。
- 2〜5件の比較は必要な求人だけ1回のbatch readで取得する。媒体の求人を同一とみなす対応付けは作らない。84項目の列名・保存順に沿った既存パーサーを使い、給与・休日を自由文から推測しない。値のある項目を比較し、違う項目に色を付け、同じ項目は折り畳む。内部IDの項目は表示対象から除く。
- AirWorkの「01」の表示経路は `baitai_genjoukyou_airwork`（媒体原ステータス_AirWORK）の生値をカード右上に表示していた箇所。プロパティは文字列型（既存調査）。01の意味との対応は未確認のため、公開状態を推測せず「不明」と表示する。

## HubSpot呼び出し回数

索引更新1回の通常時は `P + ceil(J/1000) + ceil(J/1000) + ceil(D/100)` 回。

- P: 求人オブジェクトの全件ページ数（100件/回。既存の読み取りに本文・本文履歴を追加）
- J: 媒体を判別できた索引対象の求人件数
- D: その求人に関連する重複を除いた取引件数
- 1つ目のJ/1000: 求人→取引のassociations batch read
- 2つ目のJ/1000: 求人→応募のassociations batch read（件数だけ保持）
- D/100: deals batch read（取引名）

4万件がすべて対象なら **480 + ceil(D/100)** 回。関連の続きを要求する応答があれば継続batchの回数を加算する。429・5xxの既存再試行は1要求につき最大1回追加。すべて `HubSpotClient.background()` と既存の共有ゲートウェイを通す。

API上限と関連のbatchページ分けは [HubSpotの上限変更](https://developers.hubspot.com/changelog/bug-fix-batch-read-limit-for-hubspot-associations-api) と [公式SDKのbatch仕様](https://github.hubspot.com/hubspot-api-nodejs/classes/crm_associations_v4.BatchApi.html) に照合した。既存の1秒の求人ページ間隔は維持する。追加の本文履歴はページ内の処理中だけ保持するため、全件の本文をメモリにためないが、通信量は従来より増える。
