# 求人文面管理の表示調整

2026-10-11。対象は PC 幅 1440・1920。Rust / Axum と既存 React 画面を維持する。

## 実装前の確認と方針

- `CLAUDE.md`、求人パイプライン設計、リクロジ媒体仕様、`src/job_gen/mod.rs` を確認した。
- 一覧に常時開く絞り込み、複数行の日時・説明、選択後の履歴説明があり、カードの表示領域を奪っている。絞り込みを折りたたみ、カードと日時を詰める。スクロール対象はカードのみとする。
- 通常の `/app/job-copy` は HubSpot を既定とする。明示的なデモ・固定データ確認用 URL は既存の表示を維持する。
- 求人詳細を開いた時だけ、求人→取引→会社を読む。取引の関連を一括読み取りし、会社が一意の場合のみ名前を表示する。会社の関連が曖昧・未取得なら省略する。
- HubSpot の履歴日時は本文が記録された日時であり、掲載日時とは扱わない。日時と本文を組み合わせた表記に変更する。
- 短いタイムラインに余白を設け、近い日付のラベルは段を分ける。日付・金額・応募の値は変えない。
- 求人票作成の旧メニューは高さ固定の iframe を3枚保持して切り替える。入力を保持する構造は維持し、同一オリジンの本文の高さに追従させる。

## 検証方針

合成データと API モックのみを使用する。1440×900 と表示領域 1440×690、1920×900 で、固定／マウスで開いた一覧の選択前後の完全に見えるカードを5枚以上と数える。会社名、日時、空項目の区切り、近接する印と一点の履歴、埋め込み枠の伸縮と入力保持を具体値で確かめる。変更前後の画像は `docs/screenshots/job-copy-ui-polish/`。

## 検証結果と既存の課題

- Rust 単体 4,386 件、frontend 1,792 件が通過。型検査、lint、build、`cargo fmt --check`、統計表現・CSS 検査も実施。
- 一覧・本文・画像・開閉の既存 E2E 25 件が通過。追加した近接日時の検証も通過。
- 認証された Rust シェルでも表示領域 1440×690 を含む選択前後の5枚以上、会社名・日時・空項目・近接印を確認。埋め込み枠は700pxの追加・削除に追従し、入力を保持した。
- `cargo test` 全体では今回変更しない既存の禁止識別子検査1件（別画面の5箇所）とIndeed関連のdoctest4件が失敗する。該当ソースが `origin/main` と同一であることを確認した。Rust単体・その他の統合テストは通過。
- 環境変数整合テストは従来 `var_os` を拾わず、求人文面管理の既存の読み取り設定を未使用と誤判定していた。読み取り検査を補い、既存のローカル検証用変数を `.env.example` のコメントで説明した。設定や運用は変更しない。
