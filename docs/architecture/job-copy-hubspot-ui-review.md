# HubSpot 求人一覧の画面修正と操作確認

2026-10-10。origin/main から `fix/job-copy-hubspot-listings-ui` を作成。CRM・HubSpotの書き込み・新しい永続ストアは変更しない。

## 原因をコードと動作で確認

PR #131 の画面を40求人のモックで再現した（HRハッカー30件・AirWork10件、応募者の個人情報なし）。本番ユーザーのセッション通信は採取していない。以下は同じコードによる再現の実測であり、本番の個別応答内容を断定するものではない。

- HubSpot一覧が `.jc-workspace` の外・上にあり、40行の表が左右の一覧・詳細を押し下げる。幅1440・高さ1000で一覧パネルは高さ1770px、詳細の開始位置は1905px。固定一覧は左のスクロール欄・右の詳細という構成だが、HubSpot一覧だけはこの構成に参加していなかった。
- 求人選択は `GET /api/job-copy/listings/1/versions` を1回呼ぶ。返った2版は本文各255文字・画像各1URLを持ち、`listingRecord` → `JobCopyRecord` → `CopyDetail` へ渡る。それでも詳細の初期タブが「タイムライン」で、本文・画像のパネルは hidden。本文の描画コード自体は pre で任意の文字列を表示できるが、列名と値を区切らず全文の羅列を表示していた。
- 版APIは変更履歴だけから版を作る。履歴が無い場合、現在の本文が保存されていても返ってこない。空文字の履歴では空の pre となり、状態の説明が無かった。
- 一覧準備中は1回の取得後に自動確認が無い。「求人を取得」や再読み込みが必要だった。
- 共通ナビは後から取得される。従来の高さ測定は jc-app のサイズだけを監視しており、ナビによる位置移動40pxを見落とす。祖先のサイズ変更にも追従するように修正した。

## 変更した動作

- 左の同じ一覧欄で「HubSpot の求人」「固定一覧を表示」を切り替える。デスクトップでは左幅320〜420px、右は残りの幅。両欄が画面下端まで届き、別々にスクロールする。スマホでは上下に配置し、条件を折り畳んで求人行の表示面積を確保する。固定一覧の本文・タイムライン・比較は維持する。
- 求人選択後は「求人内容」を自動で開く。右側の読み込み中・取得失敗・履歴なし・本文未取得を文章で説明する。1版だけでも表示できる。
- 案件名、キャッチコピー、仕事内容、給与等のラベルを見出しにし、複数行の値を保持する。比較と給与抽出には元の本文を渡す。`給与：月給28万円〜32万円` から280000〜320000円を検証した。
- 求人行に求人名・地域・職種・媒体・応募件数・公開状況を表示する。求人名順・媒体順に加え「表示中の応募が多い順」を用意する。応募件数は表示ページだけ取得しているため、応募順を全件の順位とは称さない。
- 準備中は約7分という初回の目安を表示し、5秒ごとに自動で確認する。APIが ready になった時点で一覧へ切り替える。正確な残り時間や進捗率は取得しておらず、表示しない。準備中の確認はメモリ参照だけでHubSpotへ追加要求しない。
- 画面読み上げ用のテキストは各求人行の内側に位置を限定する。スクロール外に配置されてスマホのページ下端に大きな余白を作っていた問題も修正した。

## 本文と画像の取得範囲

- 版APIの応答に `current` を追加。履歴から本文を得られないときだけ、同じ求人GETで取得した現在の本文を返す。フロントでは「現在の文面（履歴未取得）」と表示し、`checked_at` は今回の取得日時として説明する。保存日時や掲載開始日時にしない。
- HRハッカーは既存の本文・画像の履歴を表示する。
- 既存関所経由でプロパティ定義を1回GET（200）して確認した画像関連項目は `hrh_kyuujinhyou_gazou` と `job_copy_drive_manifest_v1`。AirWork専用の画像URL項目は見つからなかった。AirWorkの仕事内容の履歴には画像が無いため、画像を履歴に捏造しない。
- 保存済みの画像参照がある求人は、既存のDrive画像参照処理を再利用する。同じ求人GETでpointerを読み、manifestのハッシュ・対象求人を確認し、会社→取引→求人の関連を再検証する。画像URLは既存の認可付き画像APIを使う。応答の `current_images` に観測日時を含め、「現在取得できる掲載画像」「この版の保存時点の画像は不明」と明記する。元の画像履歴を置き換えない。
- 画像参照が未登録、Drive設定が無い、取得や関連検証に失敗した場合は画像を「未取得」とする。画像の無い求人に架空画像は付けない。失敗しても本文表示は維持する。
- 画像参照がある求人を選ぶと、Drive manifestの読み取りとHubSpot関連の読み取りが追加される。全一覧の索引へ画像を持たせたり、全件分の画像を事前取得したりしない。
