関連: [仕分け案](consulting-kpi-vs-job-copy-split.md) ／ [画面整理案（案件管理の入口）](https://github.com/makimaki1006/HR_HR/blob/docs/job-copy-ia/docs/architecture/job-copy-ia-plan.md)

## 1. 目的

| アプリ | 使う人 | 目的 |
|---|---|---|
| **案件管理**（`/app/job-copy`） | コンサルタント | 自分の顧客の案件と求人を、毎日の仕事として動かす。何をすべきかがすぐ分かり、その場で HubSpot を直せる |
| **コンサルKPI**（`/consulting`） | 管理職 | 部下（コンサルタント）の手が回っているか、チームとして継続・成果が出ているかを見て、手当てする。案件管理で起きたことを吸い上げて人ごと・期間ごとにまとめる |

2 つは**別のアプリのまま**にし（1 つにまとめない。2026-10-17 決定 D-4）、画面と機能をはっきり分ける。コンサルKPI は案件管理の上流のマネジメントの画面として、案件管理の情報を読む。

## 2. 利用者と権限

| 役割 | 主に使う | できること |
|---|---|---|
| コンサルタント | 案件管理 | 自分の案件・求人を見る・直す（契約・成果・ステージ・次の予定）。ほかの人の案件も見られる（代理・引き継ぎ用） |
| 管理職 | コンサルKPI | 全員の集計を見る。明細は案件管理へ飛んで見る |
| 運用担当 | 案件管理のツール | データの取込・課金 CSV・職種の指定 |
| 管理者 | 両方 | 全部 |

- **見る範囲の切り分け（決定 2026-10-17）**: コンサルKPI は管理職と管理者だけが見られる。コンサルタント（メンバー）にはナビにも出さず、URL を直接開いても見られない（画面も `/api/consulting/*` も拒否）。理由: メンバーが管理職の画面を見られると、管理されていると感じさせてしまうため。
  - 案件管理には、メンバー同士を比べる数字（担当者ごとの件数・順位）を出さない。担当者で絞るのは代理・引き継ぎのため。
  - 役割の持ち方（案）: 既存の役割（監査 DB の accounts.role、管理画面で変更。今は 管理者 / コンサルタント / BPO / 一般）に「管理職」を足す。
  - 今の状態: `/consulting` はログインした社内の人なら誰でも開ける（2026-10-17 時点）。
- D-1（決定 2026-10-17）: 管理職・担当以外の人の書き込みも許す（今のまま）。

## 3. 境界のきまり

1. **書き込みは案件管理だけ**。コンサルKPI は読むだけ。
2. **1 件ずつの明細は案件管理**。コンサルKPI は人・チーム・期間ごとの集計を出し、明細は案件管理の画面へのリンクにする。同じ明細を 2 か所に作らない。
3. **定義は 1 か所**（§7）。両方のアプリが同じ判定を使う。
4. **コンサルKPI は案件管理の記録を吸い上げる**（§6）。本文・応募者の個人情報は持ってこない。

## 8. データの元と新しさ

| データ | 元 | 新しさ |
|---|---|---|
| 案件の項目（ステージ・契約・成果・担当・予定） | HubSpot | 今の値（5 分のキャッシュ） |
| 求人・応募・課金 | HubSpot（求人の索引・応募） | 求人の索引は保存して起動時に復元。応募は 60 分ごとに作り直し（前回の結果を保存） |
| 直近 7 日の変更 | HubSpot の変更履歴 | 3 時間ごと（前回の結果を保存） |
| MTG・担当交代・電話の要約 | Google スプレッドシート（`CS_` のタブ、日次） | 前日 |
| 電話の明細 | Zoom → HubSpot（今）／シート（前日） | 案件管理は HubSpot、コンサルKPI はシート |
| コンサルKPI の集計 | シート（日次） | 前日 |

- シートの情報（MTG など）を HubSpot に戻すのは、やりたいが保留（2026-10-16）。

## 9. 動きの要件（非機能）

| 項目 | 要件 |
|---|---|
| 待ち時間 | 開いたときに「集計中」で待たせない。前回の結果を出し、時点を書き、裏で作り直す（初めての 1 回を除く） |

| 書き込み | CRM の書き込みの仕組み（競合を上書きしない・再送待ち・保存の色）を共用する |
| 保存先 | 新しい DB は作らない。捨ててよい集計は既存の監査 DB に置く |
| 表示 | 開発者の言葉を出さない。常に見るものは大きく、必要なときのものは畳む。PC 幅を先に作る（スマホは後回し） |
| 個人情報 | コンサルKPI には応募者の個人情報を持ってこない |

補足（A の場合）: 「今週・今月に直した求人」「直す前と後の 4 週の応募」には、7 日より長い期間の求人の変更の記録が要る。①HubSpot の変更履歴を期間を広げて読む（呼び出しが増える）か、②案件管理が見つけた変更を監査 DB に記録として貯める（小さな記録を 1 件ずつ足す。HR_HR 固有の永続データになるので ADR が要る）のどちらか。
