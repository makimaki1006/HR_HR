# 求人文面管理の表示調整（2回目）

2026-10-11。対象は既存の React 画面 `/app/job-copy`、PC幅1440・1920。

## 確認した問題と実装方針

必須資料（CLAUDE.md、求人連携設計、リクロジ媒体仕様、src/job_gen/mod.rs）と現行画面を確認した。表の最小幅1650pxが1440pxの詳細領域を超え、取引検索を含む絞り込み欄と別々の操作ボタンがカードの領域を圧迫していた。管理項目の空のパスワード欄、本文の「初回取得」、意味の曖昧な日時・分類状態も見直す。

1. 管理用3項目を畳んで「この項目は変更しません」と表示。既存の値保持と84項目の保存内容は維持し、編集できる81項目の空欄に「（空欄）」を表示する。
2. 画面配下の「版・取得・未取得・初回」を全件確認。本文の比較状態、本文を確認した日、応募件数・応募理由・応募者の属性・画像を確認した日時、保存された資料、読み込み操作を対象別に表現する。未取得は欠損値の表記として残し、0件とは区別する。既存のファイル形式と内部の識別情報は維持する。
3. 主な8列を既定表示し、給与形態・下限・上限を給与1列にまとめる。勤務時間・休日と給与の個別列は選んで表示でき、個別列の並び替えも維持する。給与列は下限の数値で並び替える。追加列の横スクロール時は求人名を左端に固定する。
4. 絞り込みを「条件を畳む」で閉じられるようにし、選択条件を1行にまとめる。省略された条件全文は補助表示でも確認できる。開いているときも欄の高さを制限し、求人の一覧領域を確保する。

Rust/Axum・既存の保存境界・媒体への反映方法を変更しない。HubSpot・本番・LLMには書き込み・呼び出しを行わず、APIの合成応答で確認する。
