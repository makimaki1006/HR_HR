# 求人文面管理の一覧の折りたたみ

## 現状と設計

求人一覧・絞り込み・詳細は既存の React 画面にまとまっている。求人連携の正本・取得方法・生成経路は今回変更しない。今回の表示変更と既存の求人連携設計に矛盾はない。

一覧を取り外すと、絞り込みや一覧のスクロールが失われるため、同じ要素を残して開閉する。パソコンでは通常48pxの帯、開いた一覧は詳細の上に重ねる。固定時は従来の左右配置（固定一覧300px、HubSpot一覧320〜420px）。

開く動きは180ms、マウスが離れてから250ms待つ。キーボード操作中はマウスが離れても閉じない。閉じた一覧は操作対象・読み上げ対象から外す。Escは帯、求人選択は詳細へフォーカスを移す。固定設定のみブラウザに保存し、保存できなくても操作を継続する。

## 実装順と検証

1. 表示と開閉操作を専用の小さな部品に分け、既存一覧を包む。
2. 求人選択時の閉じる操作を固定一覧とHubSpot一覧の既存処理へ追加。
3. 合成求人を使い、1440・1920pxで開閉・幅・条件保持・固定の記憶を検証。
4. 既存の常時表示を前提とする一覧テストは固定状態で実行する。
5. フロントエンド全体、Rust既存テスト、書式、PRのCIを確認する。

スクリーンショットは架空の求人のみを使用する。

## 検証結果

- `cargo fmt --check` 通過。
- `cargo test --lib`: 4385件通過、既存の51件は無視設定。
- フロントエンド: 型検査・静的検査・ビルド通過。既存136ファイル、1790件すべて通過。
- 一覧の既存8件＋新規開閉7件（1440・1920px）通過。
- Rust配信画面で新規7件、再試行なしで通過。
- 取得失敗・再取得・画像取得の既存13件と、比較・応募理由のパソコン用3件が通過。
- 閉じた詳細の幅: 1440pxでは1392px、1920pxでは1872px。固定した固定一覧ではそれぞれ1140px、1620px。
- 検索条件・並び順・選択・スクロール保持、HubSpot一覧の媒体条件・スクロール保持を具体値で検証。
- 1440pxの3状態の画像は `docs/screenshots/job-copy-collapsible-sidebar/` に保存。

ブラウザ検証はパソコン幅のみ。外部サービスのデータ書き込み・実際のLLM呼び出しは行っていない。
