# 実データ確認で見つかった表示・生成の修正

## 実装前の確認と計画

既存のRust/Axum、React画面、Gemini呼び出しとプロセス共通の関所を維持する。CRM・永続ストア・外部書き込みは変更しない。

1. HubSpot項目定義と求人の読み取り応答を確認し、AirWorkの独立した項目を比較の共通表示名へ対応させる。本文は加工せず別に保持する。金額を本文・年収から推測しない。
2. 横並びの値は数行で省略し、全文表示でも相違箇所の色を保持する。
3. 原本とAirWorkの同一文を禁止する指示を強化し、不合格時は一致文を引用して最大2回再生成。最後の検査結果と回数を返す。
4. コードは定義を確認できたものだけ表示語へ変換し、不明な数字は「確認が必要」。CSV原本の値には手を加えない。金額は桁区切り。
5. 休日は直接の休日休暇と、仕事情報補足・自由項目の休日見出しを照合する。自由項目1を無条件で休日とみなさない。
6. 索引では履歴を取得せず、表示行だけ別の読み取り窓口で50件以下ずつ取得。ページ移動時は古い応答を捨て、取得失敗時は未取得を保持。
7. 媒体名は折り返さない。

検証は本物の応答の構造を再現した架空値のモック、Rust・フロント全単体テスト、PCのE2E、1440×900の画像、CI（書式・Docker入力検査を含む）。本番の本文・名称・識別値を保存しない。

## 読み取りで確認した窓口と応答（2026-10-11）

本物のHubSpotへの書き込み・LLMの実呼び出しは行っていない。本文・名称・識別値は検証中だけ扱い、以下には形だけ記録した。

- `GET /crm/v3/properties/0-420`: `results[].name / label / type / options[]`。AirWorkの仕事内容、給与形態、勤務地、職種、勤務時間、休日、雇用形態、福利厚生の項目定義を確認。
- `POST /crm/v3/objects/deals/search`、`POST /crm/v3/objects/0-420/search`: 検索だけ。`results[].id / properties`。
- `GET /crm/v4/objects/deals/{id}/associations/0-420`: `results[].toObjectId`。求人との関連を読み取り。
- `POST /crm/v3/objects/0-420/batch/read`: `status / startedAt / completedAt / results[]`。各行は `id / properties / createdAt / updatedAt / archived / url`、履歴指定時は `propertiesWithHistory` を追加。履歴項目の配列要素は `value / timestamp / sourceType / sourceId`。欠損プロパティは `null` になり得る。
- `GET /crm/v3/objects/0-420?limit=100&propertiesWithHistory=shigotonaiyou`: HTTP 400、履歴は一度に50求人までという応答。索引は履歴を指定せず100件ずつ取得するまま。
- `POST /crm/v4/associations/0-420/deals/batch/read` と `.../0-421/batch/read`: 関連ありは `results[].from.id / to[].toObjectId`。関連なしは `errors[].category = OBJECT_NOT_FOUND / subCategory = crm.associations.NO_ASSOCIATIONS_FOUND / context.fromObjectId` と `numErrors`。このエラーだけを「関連なし」と解釈する既存の検査を維持。

手元のRustサーバーへ本物のHubSpot読み取りを接続し、ローカルの模擬OIDC認証で認証境界も通して確認した。横並びの読み取り2求人、AirWork本文・給与形態の取得、本文履歴2求人の取得を確認。画面の画像と自動テストは架空の値のみ使用。

### 数字コードの未確認事項

HRハッカーの列名・順序は84列定義と取込側の本文構成定義を照合した。一方、CSVの数字コードと表示語の正式な対応表は取得できていない。数字の意味を推測せず、試用・研修、給与の種類、雇用の種類などの数字は「確認が必要」と表示する。正式な定義が取得できたら、Rustと画面で共有する `hrhCodeLabels.json` に定義と出典を追加する。現時点で数字の対応表には未検証の割当を入れていない。原本の文字による表示名は保持する。

本文変更日は表示行だけの追加取得であり、索引全件の変更日を取得する処理は復活させない。変更日の全件順による並べ替えは今回の対象外（索引に未取得の日時を補って並べ替えない）。

## 検証

- Rustの単体・結合テスト、フロントの全単体テスト、型検査、Lint、ビルド。

- 数字コードを生の数字で出さないこと、桁区切り、仕事情報補足2や自由項目3の休日の取得。
- PC 1440・1920のE2E、1440×900の架空値の画像5枚。
- `cargo fmt --check`、Clippy、Docker builderの入力だけを使ったリリース用コンパイル検査。
