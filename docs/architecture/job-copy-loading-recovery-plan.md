# 求人文面管理の読み込み復帰

2026-10-06。既存の Rust/Axum API と React 画面を維持し、取得中の復帰操作だけを追加する。

現在の画面は初期取得失敗後にページ再読み込みを案内するが、画面内に再取得操作がない。直前の調査では実データプレビューは再読み込みで復帰したため、通信失敗だけを原因と断定しない。

実装:

- 5秒経過した取得に待機案内と再取得ボタンを表示する。進捗率や完了予定時刻は作らない。
- 再取得時は古い要求を中止し、新要求の結果だけを反映する。30秒のAPI上限を維持し、成功・失敗後は待機を終了する。
- 読み取り失敗にも再取得ボタンを表示し、既存の権限確認・再ログイン案内を維持する。
- 手動で媒体データを読み込んだ場合、初期取得を中止して後着応答による上書きを防ぐ。
- 求人本文、画像ハッシュ、応募集計、版対応、保存データ、認証境界は変更しない。

検証: 取得失敗からの再試行、遅延応答の上書き防止、タイムアウト後の表示、再ログイン案内を単体・E2Eで確認する。型・lint・既存求人テストと全体CIを確認し、同じアプリへ反映する。
