# 求人管理のセルフチェックと改善

2026-10-06。対象は既存Rust/AxumアプリのReact求人管理画面。取得済み36求人/320応募を表示したローカル実画面を今回撮影し、求人選択→本文読了→機能切替→検索0件→スマホでの求人切替を確認する。

## 実装前の観測と計画

1. 一覧・詳細：取引先と求人の選択は可能。スマホの選択後は詳細へ移るが、一覧へ戻る操作が見当たらない。詳細から一覧見出しへの戻るボタンを追加し、検索条件は保持する。
2. 長い本文：本文末尾で機能タブはviewport外にある。本文・画像・分析の数値に手を加えず、詳細内に小さなsticky操作バーを追加する。求人名と「機能を切り替える」「求人一覧に戻る」を表示し、フォーカスと表示位置を揃える。
3. 検索0件：一覧0/36件だが詳細側は「求人を選択してください」と表示する。0件に適した案内に変更し、条件があるときは一覧上部にもリセットボタンを表示する。
4. モバイル：375pxのタブ折返しと横あふれなしは維持。sticky操作が本文を覆いすぎず、200%ズーム・短い画面・キーボードで使えることを追加検証する。

今回撮影したbefore/afterスクリーンショットと原文は `data/job-copy-local/integration-validation/ux-audit-*` の私有ignored領域に保存する。内蔵ブラウザはruntime_unavailableのため、ユーザーが既に許可したPlaywrightで実画面を捕捉した。最初のモバイル撮影はスクロール前で空白だったため却下し、2回のanimation frame待機後に撮影し直して目視した。

API・認証・HubSpot/Drive・永続化・CRM正本に変更はない。既存React部品とCSSを小さく変更する。公開前に型/lint/build、job-copyユニット、操作・実データE2E、Rustを含む全体CIを実行する。本番Googleログイン後の実画面操作は別の検証であり、このローカル監査の証明に含めない。

## 修正後の確認

- 実データで5ステップを再撮影し目視。本文末尾でも求人名・操作を表示でき、検索0件の案内とリセットは1箇所に整理。375pxの横あふれなし。36求人・320応募の取得済みデータを保持した。
- job-copy unitは16ファイル158件成功。candidate E2Eは21件、実データ理由E2Eは2件成功。選択タブへのフォーカス・viewport復帰、一覧見出しへの復帰、絞り込み保持、0件から2件への復帰、横長画面でsticky解除、印刷時の操作バー除外を確認した。
- 200%拡大のリフローはCSS zoomを使う代替試験であり、OSやブラウザの実倍率操作・スクリーンリーダー実機での適合証明ではない。
- キーボード再レビューで、リセットボタンの消失後にフォーカスが失われる点を修正。リセット後は検索欄へ戻して連続検索できることをE2Eで確認する。
- 未選択タブの文字/背景のコントラスト比4.03を確認し、文字色を濃くした。実DOMのcomputed styleから比を再計算し、4.5以上をE2Eで確認する。選択状態の白背景・下線・ARIAは維持する。
- 目視した全5ステップと画像・限界は私有 `data/job-copy-local/integration-validation/ux-audit-report.html` にまとめた。公開されるドキュメントやソースに顧客画像・応募原文は含めない。

## 変更記録 2026-10-08: 注意書きと言葉の見直し（UI/UX 改修 PR4）

ユーザー判断（2026-10-08、過去の UI 決定の変更を承認）。「情報が乱立しすぎて本来の目的を果たせない」という指摘を受け、この監査で残した複数行の注意書きを 1 行 +「ⓘ 集計の前提」の折りたたみにまとめた。

- 変えた点: 各パネルの注意書きは 1 行だけを常に出し、詳しい前提は折りたたみに入れる。開発用の言葉（観測・版対応・ctk・MOC・複合集計など）を画面から外し、日時・金額・並び順の書式を揃えた。
- 守った点: HubSpot に記録された応募だけであることと、相関は因果ではないことは、折りたたみの中に必ず残す（`AssumptionsNote` が自動で足す）。欠損を 0 にしない扱いと、データの出所の表示（上部のバナー）は変えていない。
- 上部に固定するバー・「戻る」「機能を切り替える」の扱いは、この変更では変えない（配置の組み直しの PR で記録する）。

## 変更記録 2026-10-08: 上部の操作バーをなくし、最初の画面に一覧とタイムラインを並べる（UI/UX 改修 PR3）

ユーザー判断（2026-10-08、過去の UI 決定の変更を承認、求人文面管理の改修計画の決めてほしいことの 2）。この監査で残すとした「上部に固定する操作バー」と「求人一覧に戻る」「機能を切り替える」をなくした。

- 理由: 固定バーと複数行の帯が画面の上を占め、一覧の残りの高さが 99px まで減っていた。最初の画面で一覧とタイムラインを一緒に見られなかった。
- 代わりに: 上の段のタブを詳細欄の上端に固定した（本文の末尾でも機能を切り替えられる）。一覧は画面の下端まで使い、検索以外の絞り込みと並び順は「絞り込み・並び順」の 1 行にたたんだ。一覧と詳細はそれぞれスクロールするので、「一覧に戻る」は要らない。375px では一覧の下に詳細が続く。
- 上部の帯: タイトル・データの出所（操作デモ / 実データなど）・取得範囲の件数・「データ取込」ボタンを 1 行にまとめた。出所の全文は帯にマウスを置くと読める。出所の表示そのものは消していない。
- 守った点: 未選択タブの文字のコントラスト 4.5 以上、矢印キー・Home・End の操作、375px と 200% 拡大で横にはみ出さないこと、印刷時に操作部品を出さないことを、`tests/e2e/job_copy_navigation.spec.ts` で引き続き確かめる。横長で高さ 500px 以下の画面では、タブの固定を外す。

## 変更記録 2026-10-08: タイムラインのレビュー指摘への対応（修正 1 回目）

ユーザー判断（2026-10-08、過去の UI 決定の変更を承認、求人文面管理の改修計画の決めてほしいことの 2）。

- ナビの名前を「求人文面（MOC）」から「求人文面管理」に変えた（画面の見出しと同じ名前）。HubSpot から開いた求人の本文の出どころは「HubSpotの仕事内容」と書く。データ取込の文言から読み取り時間（ms）と開発用の言葉（JSON・schemaVersion）を外した。
- 書式をそろえた: 年月は YYYY/MM（時間軸の目盛り、期間比較表、市場データの終わり）。金額は画面全体で「4万5,000円」の書き方（以前のタイムラインと課金の帯は「4.5万円」だった）。
- タイムラインの給与・本文・画像の印は、右端の近く（最新の版）でも枠の中に収まるように左へずらし、開始日の位置には細い縦線を残す。
- 期間比較表: 応募日が取得できていない求人は「0件」ではなく「未取得」と書く。期間が市場データの終わり（2026-08）より先まで続くときは、データのある月で比べ「2026/09以降はデータなし」と添える。
- 市場の選び方は、職種と都道府県を別々に「自動で選んだ」「手で選んだ」と書く。
- 横断比較: 「変更前14日」は直前の版の期間の中だけで数える（それより前の版の応募を混ぜない）。直前の版が 14 日より短いときは実際の日数で数え、日数を表示する。市場は月ごとのデータなので横断比較には並べず、各求人のタイムラインの「市場」で見ることを表の上に書いた。
- 課金: 課金CSVの行が HRハッカー実績の期間と一部だけ重なるときは、HRハッカー実績を消さずに両方を残し、「期間が重なる課金あり（合計していません）」と表示する（同じ開始日・終了日のときだけ置き換える）。データ取込の「反映中」の行も、重なる期間があれば合計しない。求人の一覧を入れ替えたら、一覧に無い求人の課金CSVの反映は外す。
