# 求人管理の機能別タブ

2026-10-05。ユーザーの「機能を分けてタブで見たい」に対応する。既存Rust/Reactアプリ内のUI整理であり、API・HubSpot・Drive・認証・永続化には変更を加えない。

## 現在の表示で確認した問題

今回ローカル実データ画面を撮影・確認した。8機能が同じ階層に横並びで、応募の月次推移、市場4指標、数値表、観測履歴、要因メモが「市場・要因」の1ページに混在する。応募理由も応募者構成の中に埋まっている。private `tabs-before-desktop.png` は今回の撮影であり、既存スクリーンショットの再利用ではない。

## 実装

1. 入口を「求人内容／応募分析／市場分析／比較・報告／データ取込」の5タブへ整理する。
2. 応募分析の中を「応募推移／応募者構成／応募理由／課金・クリック」に分ける。
3. 市場分析の中を「市場グラフ／市場データ／要因・仮説」に分ける。応募推移を市場から切り離す。
4. 比較・報告は「変更差分／2求人のA/B比較／顧客報告・検証」。求人内容は「本文・画像」、データ取込は「外部文面を確認」。
5. 同じ求人内の再訪は直前の子タブ・市場の職種/県/期間・A/B条件・応募理由フィルタを保持する。求人を変えたらリセットする。値や版対応の定義は変更しない。
6. role tablist/tab/tabpanel と aria-selected/controls/labelledby を整合させ、左右キー・Home/End・選択タブへのTabフォーカスを実装する。モバイルは折返しで全機能を見せる。隠れたパネルのフォーム・グラフ・印刷が混入しないよう確認する。

## 検証・公開

コンポーネントテストで正しい機能分離と選択状態、E2Eで実績値の保全、選択の保持、キーボード操作、375pxとdesktopの撮影を確認する。既存本文/画像/理由/A-B E2Eを移行して実行。frontend typecheck/lint/build・Rustを含む必須PR CI成功後、同じ公開アプリへ反映する。今回のUI検証はユーザーが以前明示許可したE2E・反復UI監査の継続で、production Googleログインとは区別する。

## 実装後の監査

- 5つの入口と12の機能を実装。応募者構成から応募理由を分離し、応募理由にも独立した版選択を残した。顧客報告内の理由表示は維持。
- 市場グラフと数値表は同じコンポーネントの職種・県・期間状態を共有する。グラフ内の独立ズームは使わず、期間選択を共通にして数値表との対象期間のずれを防いだ。初回市場閲覧前は市場APIを呼ばない。
- 本文から差分へ遷移する際、選択タブへフォーカスとスクロールを移す。非表示フォームはTab移動と印刷に混入しない。
- 今回撮影した実データのdesktop/375px画面を目視。タブの折返し・選択表示・グラフ単位・横スクロールを確認し、ページ全体の横あふれはなかった。画像と応募原文は私有のignored領域に保存し、公開資料へ含めない。
- ローカル36求人/320応募のスナップショットで検証。ENEOS対象求人の応募2件は日付あり1件と日付不明1件を分離し、月次棒の合計1件を再計算した。市場12暦月は既存bundled DBの取得10月と欠損2月に一致した。欠損を0として扱わない。
- job-copyユニット16ファイル158件、既存画面・新ナビゲーションE2E、実データ理由E2E、型・lint・buildで検証する。全体Rust/frontendとセキュリティ等はPR必須CIで確認する。

これはUI整理の検証であり、本番Googleログイン後の表示確認や、本番認証済み市場API応答の証明ではない。ローカル実データ試験は取得済みスナップショットとbundled市場SQLを使う。

## 変更記録（2026-10-08）: タイムラインを最初のタブにする

- 決定の変更: 「5つの入口と12の機能」に、先頭の入口「タイムライン」を足した（6つの入口と13の機能）。求人を開いたときの初期タブは「本文・画像」から「タイムライン」に変わる。
- 理由（ユーザー指摘）: 情報が別々のタブに分かれていて、給与・本文・画像の変更、掲載期間、課金、応募、市場の動きを同じ時間軸で一緒に見られなかった。
- 承認: ユーザーが過去の UI 決定の変更を了承済み（求人文面管理の改修計画、決めてほしいことの 2）。
- 内容: タイムラインに 掲載期間 / 給与 / 本文 / 画像 / 課金 / 応募 / 市場 のレーンと期間比較表（1日あたりの応募）を置く。一覧の上に「一覧 / 横断比較」の切り替えを足した。既存の 5 つの入口と 12 の機能は残している（配置の組み直しは後続の PR）。
- 既存 E2E は、本文タブから始まる確認の前に「求人内容 → 本文・画像」を選ぶように直した。

## 変更記録 2026-10-08: 画面の言葉と注意書きの整理（UI/UX 改修 PR4）

ユーザー判断（2026-10-08、過去の UI 決定の変更を承認）により、次を変える。5 グループ・12 機能のタブ構成はこの変更では変えない（タイムラインの追加と配置の組み直しは別の PR で記録する）。

- 画面の言葉: 「観測版」→「取得した版」、「版対応不明」「版の対応不明」→「どの版への応募か不明」、「市場閲覧者指標（ctk）」→「Indeed閲覧者指標」、「複合集計」→「性別・年代・地域の組み合わせ集計」、「MOC」→「試作版」。サーバーや保存データから届く説明文は `format.ts` の `plainWording` で同じ言い換えをしてから出す。
- 注意書き: 1 パネル 1 行にし、残りは「ⓘ 集計の前提」（`AssumptionsNote.tsx`）の折りたたみに入れる。「応募は HubSpot に記録されたものだけ」と「並べて見るための数字で、原因は示さない」の 2 つは折りたたみから外さない。
- 書式: 日時は `YYYY/MM/DD HH:mm JST`、金額は「400万円」「25万3,400円」「1,100円」、空の値の区切り記号は出さない。年代は年齢順、都道府県は北から南に並べる。
- 因果を言い切る言葉（効果・確実に・必ず・100%）と開発用の言葉が画面に出ないことを、`wording.test.tsx` がデモの全求人・全タブで確かめる。

## 変更記録 2026-10-08: 配置の組み直し（UI/UX 改修 PR3）と課金CSVのつなぎ込み

ユーザー判断（2026-10-08、過去の UI 決定の変更を承認、求人文面管理の改修計画の決めてほしいことの 2）。上の 2 つの記録（タイムラインの追加、言葉の整理）に続けて、配置を変える。

- 上の段のタブ: タイムライン / 求人内容 / 応募分析 / 市場分析 / 比較・報告 の 5 つにした。「データ取込」はタブの列から外し、画面上部の「データ取込」ボタンで開く場所に移した。機能の数は 13 のまま（外部文面の確認も残る）。
- サブタブが 1 つしかないグループ（タイムライン、求人内容）は、サブタブの段を出さない。そのパネルは上の段のタブで名前を付ける（`featureLabelId`）。
- 「データ取込」に HubSpot の取引先・求人・応募の確認、媒体で取得した本文・画像、課金CSV、外部文面の確認の 4 つを集めた。閉じても中身は残す（読み込み途中の課金CSVを失わない）。外部文面の確認は、ここのボタンから選んでいる求人の照合画面を開き、「タイムラインに戻る」で戻る。
- 応募者の条件から求人を探す（逆検索）は、一覧の見出しの「応募者の条件で探す」ボタンで開くパネルにした。
- 上の段のタブは詳細欄の上端に固定する（横長で高さ 500px 以下の画面と印刷では固定しない）。
- 課金CSVで反映した期間は、タイムラインの課金レーン・期間比較表・横断比較の課金合計に入る。同じ求人・同じ日をふくむ HRハッカー実績の行は、課金CSVの行で置き換える（二重に数えない）。期間が重なる課金どうしは合計しない。
- 確認: `JobFeatureTabs.test.tsx`、`JobCopyLayout.test.tsx`、`tests/e2e/job_copy_navigation.spec.ts`、`tests/e2e/job_copy_timeline_preview.spec.ts`、`tests/e2e/pr/job_copy.spec.ts`。
