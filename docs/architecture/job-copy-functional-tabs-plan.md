# 求人管理の機能別タブ

2026-10-05。ユーザーの「機能を分けてタブで見たい」に対応する。既存Rust/Reactアプリ内のUI整理であり、API・HubSpot・Drive・認証・永続化には変更を加えない。

## 現在の表示で確認した問題

今回ローカル実データ画面を撮影・確認した。8機能が同じ階層に横並びで、応募の月次推移、市場4指標、数値表、観測履歴、要因メモが「市場・要因」の1ページに混在する。応募理由も応募者構成の中に埋まっている。private `tabs-before-desktop.png` は今回の撮影であり、既存スクリーンショットの再利用ではない。

## 実装

1. 入口を「求人内容／応募分析／市場分析／比較・報告／データ取込」の5タブへ整理する。
2. 応募分析の中を「応募推移／応募者構成／応募理由／課金・クリック」に分ける。
3. 市場分析の中を「市場グラフ／市場データ／要因・仮説」に分ける。応募推移を市場から切り離す。
4. 比較・報告は「変更差分／2求人のA/B比較／顧客報告・検証」。求人内容は「本文・画像」、データ取込は「外部文面を確認」。
5. 同じ求人内の再訪は直前の子タブ・市場の職種/県/期間・A/B条件・応募理由フィルタを保持する。求人を変えたらリセットする。値や版対応の定義は変更しない。
6. role tablist/tab/tabpanel と aria-selected/controls/labelledby を整合させ、左右キー・Home/End・選択タブへのTabフォーカスを実装する。モバイルは折返しで全機能を見せる。隠れたパネルのフォーム・グラフ・印刷が混入しないよう確認する。

## 検証・公開

コンポーネントテストで正しい機能分離と選択状態、E2Eで実績値の保全、選択の保持、キーボード操作、375pxとdesktopの撮影を確認する。既存本文/画像/理由/A-B E2Eを移行して実行。frontend typecheck/lint/build・Rustを含む必須PR CI成功後、同じ公開アプリへ反映する。今回のUI検証はユーザーが以前明示許可したE2E・反復UI監査の継続で、production Googleログインとは区別する。

## 実装後の監査

- 5つの入口と12の機能を実装。応募者構成から応募理由を分離し、応募理由にも独立した版選択を残した。顧客報告内の理由表示は維持。

## 変更記録 2026-10-08: round 4 の検証指摘の反映と、市場データの月・仮の課金データ

round 4 の検証で出た 15 件の指摘（反映前に作業が止まり、コミットされていなかった）を、round 5 の後のコードで確かめ直して直した。あわせて、ユーザーから次の 2 つの要件が追加された（2026-10-08）。

- 市場データ（Indeed）は毎月更新される。「2026-08 まで」をコードに書かず、`/api/job-copy/market` が返した月から最後の月を読み、「市場データは YYYY年M月まで（毎月更新）」と出す。それより後の期間はデータなしとして出す。
- 実際の課金データはまだ無い。課金レーン・期間比較表・横断比較の課金合計に、仮の課金データを出す（操作デモと実データの両方）。

変えたこと:

- 応募者の住所: サーバー（`src/geo/applicant_area.rs`）が JSON を返す前に「都道府県 + 市区町村」へ丸める。`/api/job-copy/live` の集計（性別・年代・地域の組み合わせを含む）と版ごとの集計、`/api/job-copy/moc` の保存データの集計の両方。市区町村は `src/geo/master_city.csv` にある名前だけを使い、読めないときは「（市区町村不明）」にする（推測しない）。画面側（`applicantArea.ts`）でも今までどおり丸め直す。少人数の地域を「その他」にまとめるのは画面側のまま。
- 給与の読み取り（`salaryExtract.ts`）: 「月給18〜25万円」は 18万〜25万円と読む（前は 25万円だけ）。「日給1万2000円」は 12,000円と読む（前は 10,000円）。給与の種類は最初の金額のすぐ前の語で決め、「日給月給」は月給として読む（前は行の中で最初に出た語で決めていて「時給250,000円」になることがあった）。種類と金額が合わない（時給10万円以上など）ときや、種類が書かれていない 7 桁の金額は「不明」にする（前は「年収100万円（推定表記）」と推測していた）。
- 給与の変更の判定: 給与の行の文字が前の版と違えば「給与の変更」とする。読み取った金額が同じでも、上下は「変更」（▲▼を付けない）として出し、「変更なし」にはしない。前は読み違いで同じ金額になると、給与を変えた版に何の印も付かなかった。
- 期間比較表の市場の欄: 期間がまるごと市場データの最後の月より後のときは「データなし（市場データは2026/08まで）」のように、どの月までデータがあるかを書く。
- 市場データの取得: 職種・都道府県の一覧と、選んだ職種・都道府県の月次データを、画面ごとに 1 回だけ取る（`marketSource.ts`）。求人を切り替えたり市場分析タブを開いたりしても同じデータは取り直さない。取得に失敗したものは覚えないので「再取得」は毎回サーバーへ問い合わせる。
- 市場グラフ: 職種・都道府県を選び直したとき、新しいデータが届くまで前のグラフを出したまま「市場データを取得中…」と書く（グラフを作り直さない）。
- 横断比較: 一覧の絞り込み結果を覚えておき、関係のない操作（データ取込の開閉など）で全求人の版の比較をやり直さない。カレンダーの範囲は求人ごとの比較結果から出す（同じ比較を 2 回しない）。
- 言葉: 市場分析の読み上げラベル「市場環境と応募獲得の要因」を「市場環境」にした。Indeed閲覧者指標の説明（サーバーの文）から「既存市場レポート」「上流の計測定義」をなくした。これらの言葉と「応募獲得の要因」（「・仮説」が続かないもの）は `format.ts` の言葉のチェックに入れた。
- 課金CSVの媒体名: 「constructor」「__proto__」のような名前が媒体として通ってしまうのを直した。
- 地域の丸めの準備（全市区町村の名前の整理）は、画面を開いたときではなく最初に丸めるときに行う。市区町村の一覧そのもの（約 31KB）は今も最初に読み込む JS に入っている。別に読み込むには、応募分析・応募者の条件検索・HubSpot読み取りの 4 か所で読み込みを待つ作りに変える必要があり、今回は見送った。
- 仮の課金データ（`dummyBilling.ts`）:
  - 求人ごとに、最初の版の日から応募を取得した日まで、月ごとに 2万〜8万円（1,000円単位）の架空の金額を作る。同じ求人ではいつも同じ金額になる（求人IDから決める）。
  - HRハッカーの実績や課金CSVがある日は、そちらを出し、仮の課金データはその日を除いた日数分だけにする（日数で配分）。
  - 出す場所すべてに「仮の課金データ（ダミー）」と書く: 課金レーンの見出しと注記（帯は灰色の斜線）、期間比較表の課金額の欄、横断比較の課金合計の欄と注記。実際の金額と足し合わせず「5万円 ／ 仮の課金データ（ダミー） 2万8,000円」のように並べる。横断比較を課金合計で並べ替えるときは、実際の金額がある求人を先に、仮の金額だけの求人を後に並べる。
  - 実際の課金データをつないだら `DUMMY_BILLING_ENABLED` を false にすると、画面のどこにも出なくなる。
