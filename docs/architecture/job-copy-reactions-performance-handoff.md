# 求人文面・応募理由・媒体実績・市場環境の合流仕様

## この追加で成立すること

既存 `/app/job-copy` React画面に応募理由の原記録、HRハッカー期間別実績、複合属性からの逆検索、市場環境の内部比較を追加する。求人本文を編集したりHubSpotへ書き戻す機能ではなく、応募データを関連求人の確認画面に戻す読み取り機能である。合流・本番反映の窓口は既存担当に一本化する。

応募理由は応募Object `0-421` の `oubodouki`（応募動機）、`ouboriyuu_baitaikisai`（媒体経由の原文）、`ouboriyuu_hiaringu`（一次対応の詳細）を別出典として表示する。一人に複数出典があれば記述数は複数になる。未記録・空欄・取得済み0記述を区別する。記入者やヒアリング時刻を推測しない。原文は内部閲覧用に閉じた状態から開き、通常の顧客報告・印刷から除外する。自由記述の匿名化は保証しない。

2026-10-05の読み取り監査では36求人に320応募が対応し、応募動機12件、他2出典は未記録だった。以前の317件のスナップショットと混ぜず、同じ320IDの属性を読み直してクロス集計を構築する。逆関連も確認し、319件は単一求人、1件は複数求人に関連する。後者を掲載版に配賦しない。理由と掲載版の正確な対応は未取得のため、理由の版は不明群のままにする。

## HRハッカー課金・クリック実績

求人IDは8桁の数字文字列で、先頭ゼロを保持する。HubSpot求人の `id_hrhakkaa` と媒体CSVの求人IDを対応させる。ショップIDや会社ID、HubSpot record IDと取り違えない。対象36求人の媒体IDは全件8桁・一意だった。

既存HubSpotフォルダの取得コード・CSV群から、HRハッカーの実績ファイルはまだ特定できていない。求人・応募ダウンロード、Deal請求額、Indeed検索クリックは確認できるが、それらをHRハッカー求人の課金・クリック実績として代用しない。実データ未接続の求人は0表示しない。

取り込み契約は `scripts/job_copy_attach_hrh_performance.py`。既存収集側が次の正規化JSONを渡す。実CSVの列名が未確認のため、推測したヘッダー変換を本番取得へ追加しない。

```json
[
  {
    "schema_version": 1,
    "source": "hrhacker",
    "job_id": "01234567",
    "captured_at": "2026-10-05T00:00:00Z",
    "rows": [
      {
        "period_start": "2026-09-01",
        "period_end": "2026-09-10",
        "impressions": 1000,
        "clicks": 50,
        "cost_yen": 10000,
        "applications": 5
      }
    ]
  }
]
```

上記は合成例。期間は両端を含む。欠測値は `null`。金額の税込・税別、費用の定義、表示・クリック・媒体応募の定義は取得元で統一し確認する。重複ID、曖昧な求人対応、期間重複、負値、クリック数が表示数を超える行は拒否する。全行検証後に新しい非公開スナップショットを書き出す。上書きや外部書き込みはしない。

クリック率はクリック数÷表示回数、クリック単価は費用÷クリック数、媒体応募単価は費用÷媒体応募数。分母が0または欠測なら算出不可。HubSpotの全期間応募を期間別の費用で割らない。比較画面は率のポイント差と期間日数で補正したクリック数の差を出し、課金の因果効果とは断定しない。

## Indeed市場環境と会社のブランド

`/api/job-copy/market` は同じRust認可を通し、既存 `AppState.indeed_db` と `indeed::detail::pref_series` を再利用する。新しいDBは追加しない。職種と都道府県を画面で明示選択し、月次の `job_count` / `ctk_count` / `employer_count` / `seekers_per_posting` を表示する。

現データは職種×都道府県×月56,322行、126職種・47県、2025-07〜2026-08。主キーの重複は0件。`ctk_count` は既存市場レポートの行動指標で、HubSpot応募数、HRハッカー求人のクリック、労働市場全体とは異なる。上流の計測定義と定期収集のスケジュールは未確認。最新の応募・課金期間と月次市場の期間差を確認する。この情報は内部画面に限定し、既存Indeedの社外公開方針を迂回して顧客印刷へ載せない。

ブランド力の数値は未接続。企業名検索・採用サイト閲覧・応募理由での言及・認知調査などの出典を整理する画面内メモのみ用意する。文面、画像、給与・勤務条件、課金額・表示量、市場環境、掲載期間、選考対応なども変数として残る。応募増減から会社ブランドだけを残差として断定しない。

## 将来のLLM逆検索

今回、地域×年代×性別の実際の複合集計から求人を検索できる。単変量グラフの人数を掛け合わせない。母数は取得済みの全期間応募で、不明属性も別カテゴリに保持する。最低人数で絞り、該当数・求人全応募数・比率・集計取得日を併記する。

将来LLMは自然言語を構造化条件に変換し、Rustで認可した集計検索だけを呼び出す。回答には期間、母数、欠測、対象求人・出典を付ける。勤務地と応募者居住地を区別し、日付や会社の範囲が不明なら確認する。別々の年代・性別分布から「20代男性」を推定しない。現在、LLM実行・外部への自由記述送信は実装していない。

## 反証による確認

- 8桁IDの先頭ゼロを除いた入力、数値化したID、別媒体、同一IDの複数求人は結合を拒否する。
- 期間重複・不正日付・分母欠測・0分母で、二重集計や架空のCTRを作らない。
- 複合検索の「20代男性1人」を、女性20代2人・男性30代1人と区別する。
- 理由を掲載版へ推定配賦せず、全件不明群として扱う。原文のHTMLを実行せず印刷にも載せない。
- 市場APIの未ログイン・パスワードアクセスは従来の認可境界で拒否する。

テストの確定結果と非公開Driveの新スナップショット設定は、追加実装の結果資料・統合窓口への連絡で引き渡す。本番反映や実Googleログイン成功とは別に確認する。
