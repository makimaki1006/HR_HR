# リクロジメディア向け求人案

更新: 2026-10-11 ユーザー決定を反映。対象は求人文面管理での生成・確認・CSVダウンロード。外部送信・HubSpotへの書き込みは行わない。

## 今回の設計変更

従来は数字の通常/研修・時刻の役割などの意味と文字3-gramの重なりを照合していた。文脈の例外が増え、文字の重なり率も一致した文を説明できなかった。ユーザー決定により「全文で検知→細かい単位で特定」に変更する。
新方式は原文にある数字の表記と文そのものを示すので判断理由を確認しやすい。従来方式には意味の取り違えを検知できる利点があったが、その機能は廃止する。正しい数字を違う文脈で使った誤りは担当者が確認する。画面と生成指示に限界を明記する。
保存形式・HubSpotの関連・生成モデルは変えない。永続データの移行は不要。従来方式へ戻す場合は新しい文一致の結果と画面を含めて旧実装を再導入する必要があり、単なるしきい値変更では戻らない。

## 実装方針

- 基準は読み取りサービスで取得したHRハッカー本文の全列。求人→取引→会社の関連から同じ取引先の全求人をたどる。関連の欠落・部分取得は生成を止める。
- AirWorkのみの求人では既存の正規化された求人状態を優先し、公開中を含め、公開前・公開終了を除外する。2026-10-11に読み取りで項目定義を確認した。両媒体の識別値を持つ求人ではこの状態をAirWorkのものと推測しない。AirWork固有の生状態が公開・掲載中・公開中なら含め、非公開・公開終了・掲載終了・公開開始前・未掲載・掲載停止・停止中なら除外する。それ以外・欠損は不明として含める。数値コードの意味は推測しない。
- 既存Geminiの事実抽出→原稿→84列、プロセス共通の制限を再利用。条件の数字を生成文に書かず、書くなら原文の表記のままという指示を加える。文字数・禁止表現の検査は既存と共通化し、数字にはリクロジ専用の表記一致だけを使う。
- 84列の土台を原本から写し、生成対象5列だけを差し替える。制作メモは非公開のため空欄。CSVを作成・再読込して、転記列すべての値と列順を照合する。改行・空白も完全一致。違いがあればCSVを返さず要確認。求人・店舗・画像の各スロットも照合対象。
- 数字はNFKC・桁区切りカンマ・空白をそろえ、原文全体にかたまりがそのまま含まれるかだけを見る。時刻を分へ換算する等の言い換えはしない。NFKCで面積の単位がm2になった場合も、単位内の数字を分離せず一つのかたまりとして扱う。通貨・面積・期間等の単位が原文と違う場合、数字だけの一致で通さない。無かった表記を画面に示し、その生成列を空欄にする。
- 全文が比較本文に含まれる場合は即不合格。句点・感嘆符・疑問符・改行で分割した文の一致率を相手ごとに計算し、一致した文を示す。内部空白や表現はそろえない。しきい値以上を不合格。しきい値は仮の0.2、短文の最短文字数は0。除外後に文が無い場合は未取得。

## 実測

`scripts/measure_sentence_overlap.py` は標準ライブラリだけで動く読み取り専用スクリプト。認証情報は環境変数、無ければ指定のローカルenvを読む。値は表示しない。すべての窓口を毎秒1回以下に抑えるためSearchも上限を超えない。CRMと同じアカウントの上限に余裕を残し、429ではRetry-Afterを待つ。独立プロセスなのでアプリ内のゲートウェイを直接共有するものではない。
既存の正規化された状態が公開中で、HRハッカーの識別値を持たないAirWork求人を識別値順に検索し、一意の取引先が分かる候補を最大200社取得する。会社→全取引→全求人をたどり、HRハッカーと掲載中と判定できるAirWorkが両方ある会社を集計する。本文は100件ずつまとめて読む。確認済みの関連を処理中のメモリに保持して重複した読み取りを減らす。掲載中か不明は生成時の比較には含めるが、実測の「掲載中」の標本には含めない。候補の取り方による偏りがあるため全集団の無作為標本とは扱わない。
同じ会社のHRハッカー→AirWorkの全組み合わせと、AirWorkどうしの全組み合わせを測る。一致率は方向があるためAirWorkどうしは両方向を数える。最短文字数0と8、p10/p25/p50/p75/p90/p95、0.1刻みの度数、測れなかった件数、全文一致件数を集計する。度数の最後の区間は0.9以上1.0以下、それ以外は下端以上・上端未満。分位点は線形補間。
結果は指定されたリポジトリ外の `codex-logs/rikurozi-overlap/summary.json` に件数と数値だけを保存する。本文・会社名・求人名・識別値を保存しない。本文は処理中のメモリでだけ保持する。測れない値を0へ置き換えない。アプリとスクリプトは共通の架空データの具体例で文の定義を検証する。
