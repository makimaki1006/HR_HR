# 求人の内容ポップアップ改善

## 調査と実装方針

既存の React ポップアップと job_copy の読み取り応答を拡張する。Rust / Axum、HubSpot を正本とする構成、画像取得時の顧客との関連確認を維持する。CRM、生成処理、永続化方式、外部への書き込みは変更しない。

実装前に CLAUDE.md、job-pipeline-architecture.md、rikurozi-media-api-spec.md、src/job_gen/mod.rs と、ポップアップ・一覧・取引表・本文履歴・画像取得の実装を確認した。

1. 取得済みの本文の主な空欄は「記載なし」、任意の空欄は件数付きの閉じた一覧にまとめる。本文や項目を取得できていない場合は別の表示にする。
2. 本文に対応する取得済み画像、本文内の画像 URL、最新本文の場合は別途確認した現在の画像の順に表示する。空の画像配列が後続の取得経路を妨げないようにする。ファイル名から URL を推測しない。
3. 呼び出し元の一覧に現在表示されている順序を渡し、選択先の最新の掲載本文を読む。切り替え中と端ではボタンを無効にする。失敗時は現在の求人を保持する。
4. 選択本文と直前の掲載本文を同じ行に並べ、既存の文字差分処理で変更箇所を示す。取得できない項目の比較は変更と判定しない。

## 画像が表示されない経路

- `listings.rs::image_urls` は HTTP(S) URL だけを抽出する。HRハッカーのファイル名や「画像1〜3」のファイル名だけでは画像の取得先を決定できない。
- 修正前のモデルは `version.images` が空配列でも優先し、本文にある URL と `currentImageObservation` に到達しなかった。
- AirWork の本文履歴には画像履歴を取得する処理がない。画像は既存の画像参照と取得済みの記録を、顧客との関連確認後に `/api/job-copy/image` 経由で表示する。参照が保存されていない場合や、画像の読み取りができない場合は表示できない。
- 修正前から `listingRecord` は `current_images` を `currentImageObservation` に渡している。必ず渡されていないという問題ではなく、サーバーで取得できない場合と、空配列による表示抑制を区別する必要がある。

既存の画像項目から登録有無を読み取る情報を応答に加える。HubSpot の項目追加は不要。現在の画像を過去の本文へ補わず、表示する場合は確認日時を添える。

## 検証

- 空欄の件数・表示文言、文字の変更印、順序・端の無効化、未掲載の案を選ばないこと、入力中の矢印無効化を単体テストで確認する。
- 1440×742 / 1920×742 の架空の求人で、左右の行位置、画像の表示、空欄一覧、矢印・ボタン・スクロールを確認する。1440幅のスクリーンショットは `docs/screenshots/job-copy-listing-popup-v2/` に保存する。
- フロントエンドの型検査・lint・全単体テスト・ビルド、Rust の対象テスト・書式検査、実サーバーでの対象 E2E、PR の全 CI を確認する。

## 確認結果

- フロントエンド全153ファイル・2,029テスト、型検査、lint、ビルドが通過。
- Rust の掲載履歴・画像・取得制御の12テストと `cargo fmt --check` が通過。
- 実サーバーでの対象E2E 10件が通過。追加のローカル確認では、表示中の応募数で並べ替えた後の矢印移動も確認。
- 1440×742 の12枚を保存。2列、変更だけ、画像と閉じた任意項目、開いた任意項目、左矢印移動後、登録なし、画像取得不能、AirWork画像を記録。
- 画像の登録状況そのものが不明な場合は「画像の登録状況を取得できていません」と表示し、存在を断定しない。
- 切り替え対象は呼び出し元で現在表示中の求人。ページを移動して別の50件を表示した場合は、その表示中の順序を使う。一覧の範囲外の直接リンクでは前後移動を無効にする。

## 空欄・取得不能・文字の色付けの追加検証

給与の種類・下限・上限をすべて取得して空と確認できた場合だけ「記載なし」とし、上部と本文の判定を共通にした。勤務地の明示的な空欄も現在の要約値で置き換えない。任意項目の取得範囲を確認できない場合は件数を表示せず「任意項目の記載状況を取得できていません」と表示する。

対象画面全体の「版」「取得」「未取得」「記載なし」と文字差分の描画箇所を検索した。給与タイムラインにも給与を抽出できないときの「記載なし」の断定があったため「未取得」に統一した。取り込んだ課金情報の明示的な空欄表示は保持した。

差分の共通する前後を先に分けることで、600文字でも598文字が同じ場合は変更した2文字だけを色付けする。共通文字がない場合や比較の上限を超える場合の全文置換にも色を付ける。取引の横並び比較にも同じ処理を適用し、短文・600文字・未取得同士の表示を具体値で確認した。

追加の1440幅の画像は `review-01`〜`review-04`。短文置換、600文字の一部変更・全文置換、任意項目の取得不能の4枚を保存した。
