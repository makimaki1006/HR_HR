## 2. ローカルで実行しているはずのコマンドと、必要な環境

作業の場所は、リポジトリ「Hubspot_Job-Posting」を取得したフォルダの一番上です。

### 2-1. 求人の取得(HubSpot へ書き込む)

```
python -m scripts.job_application_sync.fetchers.aw_orchestrator --phase full --from-active-deals --actual --parallel 2 --limit 20
```

- 動き: AirWork にログイン → 求人一覧のダウンロードを作成 → 完成を待つ → 取り込んで HubSpot の求人に反映。
- `--actual` を付けたときだけ HubSpot に書きます(付けないと試運転で、書きません)。
- `--limit 20` は「1回に何社まで」。`--limit 1 --headful` は、画面を見ながらの動作確認用(1社だけ)。
- 生成待ちが長い場合は、2回に分ける方法もあります(1回目: `--phase create`、少し待って 2回目: `--phase collect`)。
- 取りたい会社を指定する場合は `--target-login-ids <ログインID>,<ログインID>`。

### 2-2. 有料広告の実績(課金)の取得

```
python -m scripts.job_application_sync.fetchers.aw_orchestrator --phase billing-full --from-active-deals --parallel 3
python scripts/job_application_sync/airwork_billing_import.py --apply
```

- 1行目: 「有料広告 → 効果を分析する」から、「有料広告実績データ」を「求人」単位・直近の完了した1週間で取得。ファイルは保存先 `~/airwork-exports/billing/<週の月曜>/` に入る。
- 2行目: それを HubSpot の求人へ書き込む(`--apply` を付けない場合は件数だけ表示)。
- 初回は必ず `--headful --limit 1` で1社だけ動かし、画面の動きを目で確認する決まりになっています。

### 2-3. 必要な環境(あるはずのもの)

- Python 3.10 以上、Playwright 1.50.0(`python -m playwright install chromium` 済み)。
- 環境変数または `.env`: HubSpot のアクセス用の鍵、会社一覧シートを読む設定(シートの識別子とサービスアカウントまたはOAuthの資格情報)。
- インターネット接続(AirWork に接続できる回線。会社の固定回線か自宅回線かも後で教えてください)。

### 2-4. 結果が残る場所(確認してほしい場所)
