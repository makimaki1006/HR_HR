## 2. 生成ゲートの仕様

実装: `src/handlers/survey/handlers.rs` の `evaluate_selection_gate`(純粋関数、L765-792)と、呼び出し元 `build_survey_report_inner`(L973-1012)。

### 「明示選択」の定義

`explicit_pref` / `explicit_muni` は **クエリ(`query.pref` / `query.muni`)由来の値のみ**を指す。ダッシュボードは都道府県・市区町村を選択したときだけ `&pref=`/`&muni=` を URL に付与するため、クエリに値がある = ユーザーがダッシュボードで明示的に選んだこと、というのが前提になっている(`handlers.rs:951-957` のコメント)。
一方、CSVアップロード時に `upload_csv` がキャッシュへ書き込む `survey_pref_{session_id}` / `survey_muni_{session_id}`(CSV内で件数最多の都道府県・市区町村=「CSV dominant」)は自動値であり、明示選択には含めない。`pref` / `muni` の実行値は「明示選択があればそれ、無ければ CSV dominant」で解決される(L958-971)。

業種 (`industry`) は、クエリに無い場合 `fallback_industry_from_session`(L718-738)がダッシュボードの産業フィルタ(tower-session の `SESSION_INDUSTRY_RAWS_KEY`)から補完する。この補完後の値が `evaluate_selection_gate` に渡る `industry` 引数になる。

### 判定順(`evaluate_selection_gate` L765-792)

1. **0件ハードブロック**: 明示選択された市区町村 (`explicit_muni`) がアップロードCSVに1件も無い場合 → `GateOutcome::ZeroCount`。判定は `agg.by_municipality_salary` に `prefecture == pref && name == explicit_muni && count > 0` の行があるかで行う(`muni_in_csv`、L978-982)。CSV dominant による自動採用時は判定不要のため `true` 扱い。確認クッションでは通せない(存在しないデータでレポートは組めないため)。
2. `proceed_unselected=1` が付いていれば → `GateOutcome::Generate`(続行の明示指示)。
3. 地域(都道府県+市区町村がともに明示選択済みか)・業種(明示選択済みか)のいずれかが未選択なら → `GateOutcome::Confirm { region_explicit, industry_explicit }`。
4. 上記いずれにも該当しなければ → `GateOutcome::Generate`。

### フロー

```
明示選択あり(都道府県+市区町村+業種すべて)
  └→ 即生成 (Generate)

明示選択が一部/全部欠けている
  └→ 確認ページ「地域・業種が選択されていません。この内容で作成しますか?」を表示
       ├─ [このまま作成する] → proceed_unselected=1 を付けた URL へ遷移 → Generate
       └─ [選び直す]         → タブを閉じてダッシュボードで選び直す案内 (window.close())

明示選択された市区町村が CSV に0件 (count>0の行が無い)
  └→ ハードブロック「レポートを作成できませんでした」(確認クッションでは通せない)
```

確認ページ (`build_unselected_confirmation_page`, L836-884) は不足している項目だけを箇条書きで示す。地域が未選択なら「アップロードCSVの主要地域(◯◯)を使用します」、業種が未選択なら「業種: 未選択のため、業種別の分析(§05 第2部)は省略されます」と明記する。
[このまま作成する] のリンク先は `build_proceed_url`(L890-912)がサーバ側で元クエリの主要パラメータ(`session_id`/`variant`/`industry`/`pref`/`muni`/`theme`/`wage_mode`/`company`/`sections`/`table2e`)を復元して再構築する。これはジョブ化経路(`/report/survey/job/result/{id}`)では元クエリがURLに残らないための対応。

`variant=guide`(解説資料AI版)はこのゲートの対象外(`handlers.rs:975`)。

## 3. 地域基準のルール

実装: `src/handlers/survey/report_html/navy_report/section_02_region.rs`、市区町村統計の取得は `src/handlers/survey/handlers.rs:1294-1354`。

### 基準地域(★基準地域)

`base_muni` は `target_region`(アプリ選択を最優先で組んだ "都道府県 市区町村" 文字列)を `split_once(' ')` で分解した値で、都道府県が空でなく "全国" でもない場合のみ `Some` になる(L70-72)。この `base_muni` が §02 全体の中心点として使われる。

### 掲載シェア呼称

表2-A(件数最多10市区町村)の各行のシェア表示は、旧「中核エリア」という呼称を廃止し、「掲載シェア大/中/小」に変更した(L430-433, L535-541)。閾値: CSV総件数に対する当該市区町村件数の割合が **30%以上=掲載シェア大 / 10〜30%=掲載シェア中 / 10%未満=掲載シェア小**。「掲載シェア」= アップロードCSV件数に占める割合であることをキャプションで明記する(L584)。

### ★基準地域バッジ

表2-A では、基準地域(アプリ選択の市区町村)が件数最多10市区町村に入っていれば該当行に、入っていなければ表の末尾に行を追加してでも★基準地域バッジを表示する(`build_navy_region_table`, L564-576)。表2-D でも基準地域の行に同バッジが付き、先頭に固定表示される(`ordered.sort_by_key(|r| !r.is_base)`, L251)。

### 通勤流入の中心

表2-C(通勤流入元TOP3)の見出しは、旧「対象地域」という曖昧な表現をやめ、基準地域を流入先として名指しする(例:「通勤流入元 TOP3 (周辺地域 → 東京都千代田区)」、L205-211)。OD集計自体は元々アプリ選択pref/muniをdestとして実行されているため、表示上の名指しのみの変更。

### 2-D 市区町村比較の構成

表2-D は「都道府県平均のみ」から「指定市区町村 + 同一県内近隣 + 県平均(参考)」に変更した。

- 対象市区町村リストは、基準地域(先頭・`is_base=true`)+ 同一都道府県内でCSV件数降順の他市区町村(最大10件)、合計最大11市区町村(`handlers.rs:1298-1310`)。
- 各市区町村について失業率(`v2_external_labor_force`)・単身世帯率(`v2_external_households`)を `fetch_municipality_mean`(`src/handlers/analysis/fetch/subtab7_other.rs:326-352`)で個別に取得する。**最大11市区町村 × 2指標 = 最大22クエリ**が1回のレポート生成で発行される(§8 既知の制限も参照)。
- 取得値は `sane = |v| v.filter(|x| *x >= 0.0 && *x <= 100.0)` で0-100%域外を`None`に丸める逆証明ガード付き(`handlers.rs:1315`、2026-04-27の失業率380%流出事故の再発防止と同型)。
- `region_2d_stats` が空(HW DB未接続時など)の場合は §02 が従来の「都道府県平均比較」表にフォールバックする(`section_02_region.rs:279-297`)。

## 4. §05 の2部構成

実装: `src/handlers/survey/report_html/navy_report/section_05_companies.rs`(`render_navy_section_05_companies`, L88-540)。

### 第1部・第2部の役割

- **第1部「地域全体の企業構造(全業種)」**(L231-410): 表5-A(産業大分類構成)、5-B(急成長企業)、5-C(大手企業)、5-D(中堅企業)、5-E(採用活発企業、Fullのみ)、5-F(規模×動向6マトリクス)を **全業種**のデータで描画する。未経験採用では他業種の在職者も採用ターゲットになり得るため、まず地域全体の企業・雇用環境を示すという設計意図がコメントに明記されている(L228-230, L234-236)。
- **第2部「『(業種名)』に絞った場合の企業(直接競合)」**(L412-488): 業種フィルタ (`industry_filter`) が指定されている場合のみ描画。第1部と同じ5表を業種絞り込み版として5-B′〜5-F′で提示し、「同業種の企業に絞った姿」「直接競合となる採用主体」と明記する(L421-424)。業種未選択のまま確認クッションで「このまま作成する」を選んだ場合は、第2部を省略し「業種が選択されていないため、業種別の企業分析は省略しました」という注記のみ表示する(L481-488、`invariant_section05_part2_note_when_no_industry` テストで検証済み)。

### 実企業総数と抽出数の違い

`pool_size`(規模帯ごとに上位N社ずつ抽出した**分析対象**の社数)と `region_total_count`(対象地域の該当企業の**総数** = `v2_salesnow_companies` の実COUNT、`src/handlers/company/fetch.rs:982-1007`)は別概念であり、混同すると企業数を過小に見せてしまう。§05冒頭のリード文は `region_total > pool_size` のとき「分析対象として抽出した地域企業 N 社(対象地域の該当企業 全 M 社)」という形式で両方を明示する(`section_05_companies.rs:196-207`)。`region_total_count` は pref/muni ベースの企業取得関数でのみ実COUNTが入り、通勤圏×業種版(`fetch_company_segments_by_neighborhood_sn_industries`)では計算されない(`0`のまま)。

### band_limit

企業pool抽出の上限は、規模帯(大/中/小)ごとの取得件数 `band_limit` として `src/handlers/company/fetch.rs:782` と `:1014` に定義されている。従来 `30` だったものを `50` に引き上げた(コミットメッセージ「band limit 30->50」、コード上のコメント「2026-07-27 item29: 企業個社データを厚くするため 30→50 に引き上げ(最大150社)」)。3規模帯 × 50社 = 最大150社が pool として取得される。表への表示自体は各表とも件数最多8社に絞る(L318, L366 等の「件数最多 8 社」表記)。

## 5. 生活シミュレーション(§07 表7-I/7-J)

実装: `src/handlers/survey/report_html/navy_report/section_07_lifestyle.rs`(`build_navy_life_simulation_table` L680-780付近、`build_navy_generation_fit_block`)。新規DB取得は行わず、既存の `ctx.ext_rental_housing`(表7-H取得済み)と `median_min_salary`(表7-E/F/Hと同一値)のみを再利用する設計。

### 積算式

- 月給換算給与: 時給ベース(`is_hourly`)の場合は `median_min_salary × HOURLY_TO_MONTHLY_HOURS` で月給換算。
- 手取り概算: `月給換算給与 × NET_INCOME_RATIO_SINGLE(0.78)` (単身) / `× NET_INCOME_RATIO_FAMILY(0.80)` (家族)。
- 家賃目安: `m²単価(median_rent_jpy) × 想定面積` で算出。単身は `ASSUMED_AREA_SINGLE_SQM = 25m²`、家族は `ASSUMED_AREA_FAMILY_SQM = 70m²`。
- 残額 = 手取り概算 − 家賃目安。

### 概算係数(いずれも簡易固定係数)

| 項目 | 値 | 位置づけ |
|---|---|---|
| 手取り概算比率(単身) | 0.78 | 実際の控除額(社会保険料・所得税・住民税)は扶養人数・保険料率等で異なるとキャプションに明記 |
| 手取り概算比率(家族) | 0.80 | 同上 |
| 想定面積(単身) | 25m² | 1R/1K相当の仮の目安値 |
| 想定面積(家族) | 70m² | 2-3LDK相当の仮の目安値 |

### 代理指標の制約

`v2_external_rental_housing` には間取り(1R/1K等)の実データが存在しないため、`structure="共同住宅"` を単身向け、`structure="一戸建"` を家族向けの**代理指標**として採用している。この代理関係はキャプションで必ず明記し、断定しない(コード内コメント L611-620)。家賃データが取得できない場合はその行の家賃・残額セルのみ「取得不可」表示に留め、給与・手取り行は表示を継続する(表全体を破綻させないsilent-skip回避方針)。`median_min_salary <= 0` の場合は表7-I/7-J とも完全に省略する。

### 4段階表現(表7-J 世代適合の目安)

`build_navy_generation_fit_block` は「単身層」「子育て世帯」の2カードとも、**確認できた事実 → この情報から考えられること → まだ分からないこと → コンサルタント確認事項** の4段階を必ずこの順で提示する構成になっている(MEMORY: `feedback_neutral_expression_for_targets` 準拠、断定禁止)。使用データは単身世帯率(表7-Dと同一ソース)、ネット利用率(図7-1と同一ソース)、0-14歳人口比率(`ctx.ext_pyramid` の新規集計、`age_group_lower_bound` ヘルパーで年齢帯判定)、保育所密度(表7-Gと同一ソース)。すべて欠損の場合は空文字を返し表自体を省略する(silent skip)。

## 7. 恒久ルール

- **有効求人倍率(全職種)を職種文脈の結論に使わない**: `sp_report.rs` の経営サマリー結論一覧 (`build_conclusions`) から `conclusion_tightness`(有効求人倍率由来の結論)を除外した。「全職種の有効求人倍率を対象職種の採用しやすさの結論に接続しない」という恒久ルールがコメントに明記されている(`sp_report.rs:326-330`)。`conclusion_tightness` 自体は削除せず、§04の結論バンドでは引き続き利用する。§09のKPI表示も「売り手市場/買い手市場」等の断定語を廃し、「全国平均(約1.2倍)を上回る/同程度/下回る」という中立表現に統一した(`sev` は常に `"neu"`)。
- **禁止語「上位」**: レンダリング出力(P75ラベル、市町村ランキング図のタイトル等)から「上位」を除去し、「高い方から」「減少率の大きい」等の位置ベース表現に置換した。ソースコード内コメント(`上位 50 社ずつ` 等)は対象外(レンダリングされないため)。
- **中立表現**: 「零細企業」→「小規模企業」など、評価的に響く語を中立語に置換する方針を継続適用。
- **数値出所の明記**: 表2-Eの「全体」がCSV内県群の集計であり47都道府県全体・公的統計の全国平均ではないこと(`section_02_region.rs:330-332, 418-422`)、表5-Gの推定信頼度がMVP実装の求人数proxyであること(`section_05_companies.rs:736-742`)など、代理指標・簡易集計を用いる箇所は必ずキャプションで出所と限界を明記する。

## 8. 既知の制限

- **0件ガードの `truncate(15)` 依存(修正中)**: `agg.by_municipality_salary` はCSV件数降順ソート後に `.truncate(15)`(`src/handlers/survey/aggregator.rs:1100-1101`)で上位15件に切り詰められる。一方、選択ゲートの0件ハードブロック判定 (`muni_in_csv`, `handlers.rs:978-982`) はこの切り詰め済みリストに対して該当市区町村を検索するため、実際にはCSVにデータが存在する市区町村でもCSV内順位が16位以下だと「0件」と誤判定されハードブロックされる可能性がある。
- **表2-Dの最大22クエリ**: 基準地域+同一県内近隣(最大10件)=最大11市区町村について、失業率・単身世帯率の2指標をそれぞれ個別クエリ (`fetch_municipality_mean`) で取得するため、1回のレポート生成で最大22件のDBクエリが直列に発行される(`handlers.rs:1294-1354`)。
- **家賃の県フォールバック条件**: `fetch_rental_housing`(`src/handlers/analysis/fetch/subtab5_phase4.rs:657-712`)は、選択市区町村の家賃行があればそれを優先し、無い場合のみ県集計行(`municipality`が空の行)+全国比較行にフォールバックする。フォールバック発生時は表7-Hに「※ 対象市区町村単位の家賃データが無いため、都道府県集計値を表示しています。」という注記が付く(`section_07_lifestyle.rs:519-527`)。`muni` が空文字列(consult/jobmap経由等、SP本編以外の呼び出し)の場合は従来通り県+全国のみを返す従来経路が維持される。

## 9. 運用ノート

- **include_str! 系のリビルド必須**: 本改修で変更した各セクション(`navy_report/*.rs`)はいずれもRustソース内で直接HTML文字列を組み立てる実装であり、テンプレートファイルの `include_str!` 読み込みではない。ただしプロジェクト全体では `report_html/mod.rs` / `db_columns.rs` / `region.rs` が `include_str!` を使用しているため、これらに関連する変更を行った場合はビルド(`cargo build`)によるリビルドが必須である点は他ドキュメント同様に留意する。
- **設計書の所在未確認**: `section_07_lifestyle.rs` のコメントは生活シミュレーション実装の根拠として `life_affordability_design.md`(A案: §07末尾統合)を参照しているが、リポジトリ内を検索した限りこのファイルは見つからなかった。設計書自体は本ファイルの対象外のため、内容の転記はしていない。
- **関連する既存ドキュメント**: 生活費・スコアリング関連の先行検討として `docs/SURVEY_MARKET_INTELLIGENCE_PHASE3_PLUS_LIVING_COST_AND_SCORES.md` が存在する(本改修との直接の参照関係は diff からは確認できていない)。
- **テスト**: 本改修に伴い `src/handlers/survey/report_html/invariant_tests.rs` に逆証明テストが追加されている。表2-Dの市区町村比較(基準地域バッジ・県平均参考行・0-100%域ガード)、表2-Aの掲載シェア呼称、§05第2部の省略注記、選択ゲート (`evaluate_selection_gate`) の単体テスト(`handlers.rs` 内、7ケース)が該当する。
