# 日程のやりとりの順番 (2026-10-14)

人材サービス会社の営業が法人の採用担当にかけた電話。目的は中途採用支援サービスのオンライン面談の日時を取ること。形式 `[開始秒] 営業|先方: 発言`。先方は受付と担当者が同じ話者。ASR の崩れがある。
営業はふつう、最初の打診で「〇日の10時か11時」のように日時の候補を出す。

**確かめたいこと:** 日程の断り(その日は無理・忙しい 等)のあとに、営業が日付と時刻の具体的な候補を出しているのは、
- 営業が自分から先に出しているのか(先回り)、
- 先方が先に手がかり(「〇日なら」「午後なら」「その週は空いてる」等の前向きな返事)を出したのを受けて、時刻を付けて回収しているのか(回収)。

どちらが多いかを、電話ごとに順番で記録する。

**見る範囲:** 最初の打診から、日時の了承まで(了承が無ければ電話の終わりまで)。

## 項目

| key | 定義 |
|---|---|
| sched_obj_sec | 最初の打診のあと、先方が最初に日程を理由に断った・渋った発言の秒。無ければ null(以下の項目は全部 null か空) |
| exchanges | sched_obj_sec 以降の日程のやりとりを、出た順にリストで。各要素は `{sec, who, kind, spec, quote}`。<br>who: `営業` / `先方`。<br>kind: 営業なら `候補を出す` / `相手に聞く` / `時期だけ決める` / `引く`。先方なら `手がかり`(空いている日・時間帯・「〇〇なら」・前向き) / `断り`(その日も無理・分からない 等) / `了承`。<br>spec(候補や手がかりの具体さ): `日と時刻` / `日だけ` / `時間帯だけ` / `週・時期だけ` / `なし`。<br>quote は30字以内 |
| first_clue_sec | 先方が最初に `手がかり` を出した秒。無ければ null |
| first_rep_dt_sec | 営業が日程の断りのあと最初に `日と時刻` の候補を出した秒。無ければ null |
| rep_dt_mode | `先回り`(first_rep_dt_sec が first_clue_sec より前、または手がかりが無いのに出した) / `回収`(先方の手がかりの後に、それに時刻を付けて出した) / `出していない` / `日程の断りなし` |
| deferral_mode | 先方が先送り(来月・落ち着いたら 等)をしたとき、具体的な日付を最初に言ったのはどちらか。`営業が先に日付を出した` / `先方が先に日付か時期を言った` / `日付にならなかった` / `先送りなし` |
| note | 迷った点を一言 |

## 出力
1件1行 JSONL。入力の全 call_id を入力順に。キーは call_id と上の表のものだけ。
