# 通話ラベル判定の基準 (ユーザー合意済み 2026-10-13)

人材サービス会社の営業(佐藤 / 斎藤)が法人の採用担当にかけた電話の文字起こし。
形式: `[開始秒] 営業|先方: 発言`。先方は受付と担当者が同じ話者になっている。ASR なので社名・人名・数字は崩れることがある。

注意: 営業は初めての相手にも「前回〇〇の件で」「ご無沙汰しております」と入る(社内で「既存感」と呼ぶトーク)。この言い方だけで「既存のアポがある」とは判断しない。

## ラベル(1件に1つ)

| label | 定義 |
|---|---|
| got | この電話の中で、**新しい**面談(打ち合わせ)の日付と時刻が決まり、担当者が了承した。目印: 営業が日時を復唱する、Zoom リンク・アンケート・メールの送付を予告する、メールアドレスを確認する |
| tentative | 日時の候補は出たが、担当者が「確認して折り返す」「上に聞く」などで保留し、了承していない |
| lost | 担当者に日程を持ちかけたが、断られた、または「また連絡する」「時期を改めて」で日程が決まらなかった。一度決まった日程がこの電話の中で取り消された場合もこれ |
| ended_before_proposal | 担当者と話したが、日程を持ちかける前に電話が終わった(冒頭で「募集していない」「結構です」と切られる 等) |
| excluded | 次のどれか。exclude_reason に書く: `absent`(担当者不在・外出・休み・退職・受付止まり・留守電・伝言のみ) / `existing_appointment`(すでに決まっているアポの確認・リマインド・リスケ。リスケで新しい日時が決まってもこれ) / `noise`(保留音だけ・文字起こしが崩れて判断不能) / `other`(窓口確認だけ、営業電話でない 等) |

判断の補足:
- 決まった後で電話の終わりに相手が消極的な言葉(「微妙」「話になるかどうか」)を言っても、日時が了承されていれば got。
- 「本日〇時からのお打ち合わせの件で」「先日お約束した〇日の」のように、**この電話より前に決まったアポ**に触れている電話は existing_appointment。既存感の「前回は〜」(以前話したことがある、打ち合わせが流れた)とは区別する。
- 受付で一度止まり、その後担当者につながった場合は、担当者との会話で判断する。

## 出力

1件1行の JSONL。キー:
```json
{"call_id":"...","label":"got|tentative|lost|ended_before_proposal|excluded","exclude_reason":null,"evidence_sec":123,"evidence":"根拠の発言を短く引用(60字以内)","note":"迷った点があれば一言。なければ空文字"}
```
- evidence_sec は根拠の発言の開始秒。
- 入力にある全 call_id を、入力の順に1行ずつ出す。抜けや重複を作らない。
