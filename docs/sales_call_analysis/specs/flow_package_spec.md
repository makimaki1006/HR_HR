# 冒頭から結果までを、前後の流れごと書き出す(2026-10-15)

人材サービス会社の営業が、法人の採用担当にかけた電話です。目的は中途採用支援のオンライン面談の日時を取ること。形式は `[開始秒] 営業|先方: 発言`。ASR の崩れがあります。営業は初めての相手にも「前回〇〇の件で」と入ります(既存感のトーク。文面だけで本当に再接触とは判定しない)。各電話に「打診の秒」(最初に面談の日時を打診した秒の目安。null もある)と結果が付いています。

採用担当(または決める立場の人)とつながった後の流れを書き出してください。受付とのやりとりは除きます。

**秒は、文字起こしの行頭の `[秒]` をそのまま書く。引用は書かず、秒で指す**(こちらで原文を取り出します)。該当が無いキーは null または空配列。

| key | 定義 |
|---|---|
| reached | 採用担当(決める立場の人)と話せたら true。受付止まり・不在なら false(以下は null でよい) |
| open_secs | 担当者につながってからの、営業の冒頭の行(挨拶 → 前回・件名 → 理由 → 打診まで。1〜4行) |
| why_secs | 「今かける理由」(なぜ今電話したか: 先方が前に言った時期、サービスの更新、市況、担当変更、他拠点の実績、期間が空いた、など)を言った行。無ければ [] |
| prop_sec | 営業が最初に面談の日時(日付・時刻・都合)を打診した行。無ければ null |
| first_sec | 打診(無ければ冒頭)の直後の、先方の最初の実質的な返事の行 |
| first_type | `了承` / `条件付き前向き`(午前なら・30分なら・来週なら) / `日程の断り`(その日は無理・忙しい) / `需要の断り`(募集してない・間に合ってる・他社がある・予算がない) / `質問`(何の件・どこの会社・前回って何・何をする会社・費用・形式) / `先送り`(また連絡して・時期が来たら) / `担当違い` / `思い出せない・前回の否定` / `その他` |
| rounds | 先方の第一声の後のやりとりを、先方の返事 → 営業の応じ方 の組で順に最大6組。各組 `{"m_secs":[営業の応じ方の行の秒1〜2], "m":応じ方, "ack":受け止めの一言(失礼しました・そうですよね・承知しました 等)が応じ方の頭にあれば true, "p_sec":その応じ方への先方の次の返事の行の秒, "p":返事の型(first_type と同じ選択肢)}`。1組目の m は first_sec への応じ方。m の選択肢: `具体的な日時`(日付+時刻) / `日付・週だけ` / `都合を聞く` / `負担を下げる`(15分だけ・電話で・オンラインで) / `質問に答える` / `違い・価値を足す` / `採用状況を聞く` / `次の電話を約束` / `資料送付` / `引き下がる` / `確定に進む`(了承の後の詰め) / `その他` |
| date_tries | 先方の第一声の後に、営業が日時(日付・時刻・都合・負担を下げた日時)を出し直した回数 |
| end | `日時が決まった` / `次の電話の約束` / `資料送付` / `決まらず終了` / `判断不能`(記録が途中で切れている等) |
| end_sec | 結果が決まった行(日時が決まった行、または断られて終わる行) |
| precondition | トークの出来とは別に、結果を左右したと思われる先方の事情を30字以内で(例: 「既に他社で充足」「採用予定が来春」「本部が決める」「前回、9月以降と言っていた」)。無ければ `なし` |
| pattern | この電話の流れを一言で(20字以内、自由記述。例:「時期のお礼→再断りに時刻を出し直し決定」) |
| lesson | 真似するときの条件: この電話のトークが効いた(効かなかった)のは、前後のどの条件があったからか(60字以内) |

## 出力
1件1行の JSONL。入力の全 call_id を入力の順に。キーは call_id, got(結果が「アポが取れた」なら true)と上の表のもの。
