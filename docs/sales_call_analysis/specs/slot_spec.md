# 提案した時間帯と、日程の断りのあとの手順 (2026-10-14)

人材サービス会社の営業が法人の採用担当にかけた電話。目的は中途採用支援サービスのオンライン面談の日時を取ること。形式 `[開始秒] 営業|先方: 発言`。先方は受付と担当者が同じ話者。ASR の崩れがある。
どの営業の電話か、結果がどうだったかは伏せてある。

## A. 提案した時間帯(電話全体)

| key | 定義 |
|---|---|
| slots | 営業が面談の候補として出した日時を、出た順にすべて。各要素は `{sec, day_expr, rel, weekday, time_expr, hours, reason, quote}`。<br>day_expr: 言った日付表現そのまま(「明日」「17日」「来週の水曜」)。<br>rel: `今日` / `明日` / `明後日` / `今週` / `来週` / `再来週以降` / `不明`。<br>weekday: `月`〜`日` / `不明`。<br>time_expr: 言った時刻表現そのまま(「10時か11時」「午後」「朝一」)。<br>hours: 時刻を数字のリストで(「10時か11時」なら [10,11]、「2時」は文脈で14、「午後」だけなら [])。<br>reason: その時間を選んだ理由を営業が言っていれば短く(「朝一なら落ち着いていると思うので」「お昼休みに」等)。無ければ空文字。<br>quote は30字以内 |
| prospect_slot | 先方が自分から言った空き時間・時間帯(「午後なら」「夕方なら」「月曜はダメ」等)を出た順に。各要素は `{sec, expr}`。無ければ空リスト |
| agreed_slot | 最終的に了承された日時の表現(無ければ空文字)と、その hours |
| industry_hint | 先方の業種・職種が会話から分かれば短く(「運送」「製造」「介護」等)。分からなければ空文字 |

## B. 日程の断りのあとの手順(日程の断りが無い電話は全部 null)

| key | 定義 |
|---|---|
| sched_obj_sec | 最初の打診のあと、先方が最初に日程を理由に断った・渋った発言の秒。無ければ null |
| ask_day_only | 日程の断りのあと、時刻を外して日付や週・曜日だけを**問いかけの形**で出したか(「翌週とかの方が良さそうですかね?」「水曜木曜とかの方が?」)。`した` / `しなかった` |
| ask_constraint | ダメな日・目処など、先方の制約を言わせる質問をしたか(「絶対ダメな日ってあります?」「何日ぐらいなら目処ですか」)。`した` / `しなかった` |
| switch_to_demand | 日程の断りの直後(営業の次の1〜2発言)に、日程の話を離れて採用状況を聞いたか(「募集されてますか」「充足されてますか」)。`した` / `しなかった` |
| first_clue_sec | 日程の断りのあと、先方が最初に手がかり(空いている日・時間帯・「〇〇なら」・前向きな返事)を出した秒。無ければ null |
| note | 迷った点を一言 |

## 出力
1件1行 JSONL。入力の全 call_id を入力順に。キーは call_id と上の表のものだけ。
